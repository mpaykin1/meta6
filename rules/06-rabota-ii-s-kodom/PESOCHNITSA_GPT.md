## ПЕСОЧНИЦА — ChatGPT работает без ограничений, но ничего не может сломать (решение владельца 06.11.2026)

**Зачем.** У Claude токены кончаются быстро, у ChatGPT — безлимит. Сливать в основной проект META GAMES без Claude запрещено. Противоречие (ТРИЗ): ChatGPT должен иметь доступ, чтобы работать, и не должен иметь доступа, чтобы ничего не сломать. Решение — разделить «где», «когда» и «по какому условию».

### 1. Разделение в пространстве — песочница
- **Основной проект `mpaykin1/meta6` для ChatGPT — только чтение.** Никаких коммитов, push, merge и мерджа PR в `meta6`. Защиту ветки `main` не трогать и не ослаблять. Читать и копировать код оттуда можно.
- **Песочница `mpaykin1/meta6-lab`** — копия `meta6/main` со своим бесплатным GitHub Pages: `https://mpaykin1.github.io/meta6-lab/meta-games/`. Там ChatGPT может делать всё: писать, пробовать, ломать.
- **Каждая идея — отдельная ветка `lab/<короткое-имя>`** и своя ссылка, чтобы поиграть именно в неё. Разные идеи в одной ветке не смешивать.
- Все правила `AGENTS.md` действуют и в песочнице (ЧИСТЫЙ ЭКРАН, ЗВУК, БЕЗ ПОВТОРОВ, ПОСТЕПЕННО, ПОНЯТНАЯ ПОЛЬЗА, ВИДИМО И ЭКОНОМНО, REUSE).

### 2. Разделение во времени
- ChatGPT работает в песочнице всё время.
- Claude, когда у него есть токены, только **забирает** готовые идеи в `meta6` и дописывает свои нужные части. Переносит в `meta6` только Claude.

### 3. Разделение по условию — фильтр
Идея попадает в очередь на забор, только если:
1. бот прошёл все уровни, ошибок в консоли нет, FPS на телефоне не упал (зелёный прогон GitHub Actions — ссылка);
2. к каждому утверждению есть доказательство: ссылка, SHA или прогон Actions — без доказательств не принимается;
3. владелец поиграл и сказал «нравится».
- Нашёл ошибку → обязан сам исправить и только потом сообщать. Отчёт «я нашёл ошибку» без исправления запрещён.

### 4. Идеальный конечный результат — Claude тратит минимум токенов
В корне `meta6-lab` файл `LAB_QUEUE.md`. На каждую идею — карточка не длиннее 15 строк:
- название и что даёт игроку (1–2 простых предложения);
- ссылка поиграть;
- ветка и SHA последнего коммита;
- изменённые файлы и сколько строк;
- ссылка на зелёный прогон бота;
- статус: ГОТОВО К ПРОВЕРКЕ / В РАБОТЕ / ОТКЛОНЕНО;
- «Михаил: нравится / не нравится» — заполняется только по словам владельца.

Изменения делать маленькими, понятными, по возможности отдельными файлами-модулями — чтобы Claude прочитал одну карточку, а не весь код.

### 5. Как Claude забирает
1. Читает `LAB_QUEUE.md`, берёт только карточки «ГОТОВО К ПРОВЕРКЕ» + «нравится».
2. Переносит изменения в `meta6` (cherry-pick или копия модуля), дописывает свои части, проверяет ботом.
3. Ставит в карточке «ЗАБРАНО → <SHA в meta6>».
