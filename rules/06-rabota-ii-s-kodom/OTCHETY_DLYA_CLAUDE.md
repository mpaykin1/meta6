# ОТЧЁТЫ ДЛЯ CLAUDE — все результаты работы всегда видны на GitHub

**Решение владельца 07.11.2026. Обязательно для ChatGPT, Codex и всех агентов.**

Простыми словами: Claude в любой момент открывает GitHub и видит, что сделано, что сломано и почему. Ничего важного не живёт только в чате ChatGPT.

Claude читает GitHub через подключённый аккаунт (GitHub API: PR, прогоны Actions, ошибки проверок). Ключи и токены никому не передавать и никуда не вставлять.

## 1. Где должен лежать каждый результат

1. **Любая работа — ветка и PR** в публичном репозитории (`mpaykin1/meta6-lab`, `mpaykin1/World_server`). Работа без PR считается несделанной.
2. **Описание PR** — всегда свежее. После каждого нового пуша обновить в описании: что сделано, зачем, ссылка на последний прогон бота и проверок, итог (PASS/FAIL) и причина, если FAIL.
3. **Любая проверка — прогон GitHub Actions.** Причина провала пишется в лог как аннотация `::error title=...::понятная причина` и в сводку `$GITHUB_STEP_SUMMARY` (таблица). Прогон без понятной причины провала — плохой прогон, исправить.
4. **Карточка в `LAB_QUEUE.md`** песочницы для каждой идеи: ссылка поиграть, ветка и SHA, PR, прогон бота, статус. Карточку обновлять при каждом изменении статуса.
5. **Итоговое сообщение** ChatGPT продублировать комментарием в PR (таблица «шаг | PR | SHA | прогон | итог»).

## 2. Что запрещено

1. Результаты, ошибки и решения только в чате ChatGPT, в личных файлах, вне GitHub.
2. Доказательства только внутри скачиваемых артефактов без строки в сводке прогона.
3. Удалять или переписывать прогоны, PR и комментарии с провалами, чтобы скрыть ошибку.
4. Приватные репозитории и закрытые ссылки для отчётов.
5. Новые файлы-отчёты в репозитории (правила автозадач): отчёт — это PR, прогон, комментарий и карточка, а не отдельный файл.

## 3. Проверка Claude

Claude смотрит: открытые PR в `meta6-lab` и `World_server`, их последние проверки, аннотации провалов, `LAB_QUEUE.md`. Если для какой-то работы этого не хватило, чтобы понять результат, — работа не засчитывается и возвращается ChatGPT.

## 4. Проценты готовности и проверка честности (07.11.2026)

1. Проценты MCP, Библиотеки и Бота считает только скрипт Claude `scripts/meta-progress/progress.mjs` по живым фактам (ответы MCP, файлы, прогоны META BOT). Оценки на глаз запрещены.
2. Песочница запускает его через `.github/workflows/lab-progress.yml` каждые 3 часа и пишет итог в issue «Готовность META GAMES — отчёт» (метка `progress`).
3. Отчёт ChatGPT — комментарий в этом issue, первая строка `ОТЧЁТ GPT`. Его сразу проверяет `scripts/meta-progress/verify-report.mjs`: каждая ссылка на PR, коммит и прогон должна быть настоящей, «слит» — правда слит, «прошёл» — прогон зелёный, проценты — равны измеренным. Ошибки ChatGPT исправляет сам и публикует отчёт заново.
4. Владельцу в чат — только названия и проценты из последнего измерения (вместе с разделом 5).

## 5. Отчёт владельцу — только то, что ещё осталось сделать (решение владельца 07.11.2026)

Простыми словами: владелец не читает, что уже сделано. Он хочет видеть только, что ещё не готово.

1. Сообщение владельцу в чате состоит **только из списка «Осталось сделать»**: каждая строка — что не готово, одной простой фразой, и что этому мешает (если мешает).
2. Запрещено перечислять владельцу сделанное: «создан PR», «слит», «добавлено», «проверил», «завершено». Всё сделанное живёт только на GitHub (PR, прогон, карточка LAB_QUEUE, комментарий `ОТЧЁТ GPT`) — Claude проверит его там.
3. Ссылки и SHA-доказательства сделанного пишутся в PR и в issue «Готовность META GAMES — отчёт», а не в сообщении владельцу.
4. Если всё готово и ничего не осталось — одна строка: «Осталось: ничего».
5. Нашёл ошибку — сначала исправь, в отчёт она попадает только если исправить не удалось, как пункт «Осталось».

Образец:
```
Осталось сделать:
1. MCP PR #621 не слит — упёрлись в лимит Cloudflare.
2. Публичный каталог не обновлён — ждёт слияния #621.
3. Generated Confluence Vault собрана из неэталонных ассетов — пересобрать из пяти эталонов.
```
