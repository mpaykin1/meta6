# META GAMES → Steam: цель и подробный план реализации

**Решение владельца: 06.11.2026.** Статус: **ЦЕЛЬ ПРИНЯТА; ИНТЕГРАЦИЯ ЕЩЁ НЕ РЕАЛИЗОВАНА**.

Связано с основной [целью платформы](META_GAMES_PLATFORM.md), [правилом источников](../06-rabota-ii-s-kodom/META_GAMES_SOURCE_ALLOWLIST.md), [чек-листом качества](RULES_CHECKLIST.md). Это дополнение, а не замена существующей архитектуры, 7 движков World_server, общей библиотеки `shared/`, автоправки и бота.

## 1. Конечная цель владельца

Опубликовать **META GAMES как единое приложение в магазине Steam**. Когда разработчик или Claude/ChatGPT добавляют очередную игру в `mpaykin1/meta6`, Steam-версия должна получать эту игру **внутри общего каталога META GAMES**, без ручного переноса файлов, переписывания игры и оформления каждой игры как отдельной карточки Steam.

- Одна карточка META GAMES в магазине, одна установленная платформа, единое меню и переходы между мирами.
- Все подходящие игры — реальные запускаемые HTML/WebGL-проекты, не просто ссылки на сайты.
- Новые игры автоматически подхватываются сборщиком из GitHub после допуска по качеству, правам и требованиям Steam.
- Игрок получает новые игры **через обычные обновления Steam**. Обновление каталога в GitHub само по себе НЕ означает мгновенную доставку игры в уже опубликованную Steam-версию.
- Добавление игры в META GAMES НЕ создаёт отдельную карточку в магазине Steam. Для отдельного Steam AppID требуется самостоятельная процедура публикации и плата.
- Существующий сайт META GAMES, Playgama, одобренные оригиналы, Netlify и пять автозадач ChatGPT остаются нетронутыми.

**Граница автоматизации:** GitHub → подготовка и проверка пакета → автоматическая загрузка в SteamPipe (после подключения Steamworks) → тестовая ветка Steam. Перевод нового билда в публичную ветку `default` выполняется в Steamworks ответственным издателем: официальная документация SteamPipe указывает, что `SetLive` автоматически работает для beta-веток, но **не для `default`**. Поэтому обещать полностью автоматическую публикацию для всех покупателей после каждого коммита нельзя.

## 2. Продукт и технический принцип

**Основной вариант:** упаковать существующую платформу и игровые HTML/CSS/JS/WebGL-ресурсы в настольное приложение **Electron** для Windows (первый релиз), затем рассмотреть macOS/Linux/Steam Deck. Electron — оболочка; внутренняя графика, GLSL, логика игр и склад ассетов остаются исходными, без перерисовки. Зависимости оболочки являются инфраструктурой, а не новыми донорами игрового кода.

- Начальный экран — общий каталог/живой мир META GAMES. Каждая игра запускается локально из собранного пакета.
- Контент включён в Steam depots и доступен **без стороннего CDN** для базового запуска. Не подменять SteamPipe внешним загрузчиком игровых файлов: Steam рекомендует доставлять контент и обновления средствами Steam.
- Можно по сети обновлять **метаданные** (названия/обложки/анонсы), но нельзя объявлять удалённую игру установленной и доступной, пока её файлы не попали в локальный Steam-билд.
- Steam-специфичные настройки изолировать в адаптере, не изменяя игровые эталоны, принимаемые владельцем, и не копируя `shared/` по каждой игре без необходимости.
- Различие платформ: веб-версия может использовать рекламу по своим правилам; **Steam-сборка отключает всю рекламную монетизацию, включая Adsterra, rewarded/interstitial и вознаграждения за просмотр рекламы**. Официальные правила Steam не поддерживают рекламную бизнес-модель внутри игр.

## 3. Архитектура синхронизации

```text
GitHub meta6/main (игры и shared/)       World_server (7 движков)
               |                                  |
               +--------- готовый артефакт -------+
                                  |
                      каталог + манифест игр
                                  |
                    проверка прав и качества
                                  |
                     сборщик Steam-пакета
                                  |
                       SteamPipe / beta
                                  |
                 публикация default в Steamworks
                                  |
                   Steam-клиент обновляет игру
                                  |
               META GAMES показывает новую игру
```

**Предлагаемые новые, незащищённые файлы (создавать по мере реализации):**

- `apps/steam-shell/` — Electron main/preload, собственное окно, локальный роутинг миров, безопасное хранение сохранений.
- `steam/catalog.schema.json` — контракт записи игры: уникальный `id`, `title`, `version`, `entry`, `assetManifest`, `rightsStatus`, `botStatus`, `steamEligible`, `releaseNotes`.
- `steam/catalog.json` — формируемый список разрешённых игр; источник — действующие игровые манифесты и подтверждённые папки, а не выдуманные имена.
- `scripts/steam/build-catalog.mjs` — обнаружение новых игр, проверка локальных путей и ссылок, устранение дублей, сортировка и версия каталога.
- `scripts/steam/package.mjs` — упаковка оболочки, игр и их реальных зависимостей в воспроизводимый пакет.
- `.github/workflows/steam-package.yml` — бесплатная CI-сборка и артефакт без доступа к Steam для каждого подходящего изменения.
- `.github/workflows/steam-beta.yml` — **только после готовности Steamworks**, при наличии секретов, загрузка в тестовую ветку SteamPipe; без автопродвижения в публичный `default`.

Названия — проектная спецификация, не утверждение, что эти файлы уже существуют.

## 4. Этапы реализации

### Этап 0. Правила распространения и регистрация (Steamworks)

1. Зарегистрировать правообладателя/издателя в Steamworks, оформить налоговые, банковские и идентификационные сведения. Это делает владелец в Steamworks; ИИ не может подменить KYC.
2. Оплатить Steam Direct Fee **$100 за приложение** (возможны применимые налоги); получить AppID и права доступа к depot/сборкам. Бюджет разработки — бесплатные инструменты, **обязательный сбор Steam не бесплатный**.
3. Уточнить у Steamworks/Support допустимость именно единого приложения с коллекцией игр, которое пополняется обновлениями, и правильно описать его в магазине. Не маскировать стороннюю площадку ссылок под полноценную игру.
4. Выбрать модель: платная покупка или бесплатное приложение с поддерживаемой Steam монетизацией. Не переносить рекламную модель с веба. Подготовить честное описание ассортимента игр и обновляемого каталога.
5. Учесть обязательную предварительную проверку Valve, «Скоро выйдет», ожидание перед первым релизом; текущие сроки брать из Steamworks в момент подачи.
6. Заполнить Content Survey, включая использование **предварительно созданного ИИ-контента** (Claude/ChatGPT), а при реальной генерации во время игры — требования к защитным ограничениям live-generated AI.

**Готовность:** подтверждённый издатель, AppID, разрешённая продуктовая концепция и доступ SteamPipe. До этого этапа никакой автоматической публикации в Steam нет.

### Этап 1. Единый каталог игр

1. Прочитать реальные источники `meta-games/`, `games/` и имеющиеся JSON-реестры; не подменять физически существующие игры записями из памяти.
2. Для каждой игры оформить минимальный машиночитаемый паспорт с точкой входа, зависимостями, версией, типом управления, источником, статусом прав и готовностью для Steam.
3. Выровнять идентификаторы веб-каталога и Steam-каталога; никаких дублирующихся карт по разным путям.
4. Включать новые игры по явному условию **Steam-ready**, а не по одному факту появления папки. Игра, ещё не прошедшая проверки, не попадает в сборку.
5. В Steam отображать только реально упакованные и запускаемые игры. Новые карточки добавлять автоматически вместе с соответствующими файлами.

**Готовность:** после добавления одной допущенной игры каталог собирается заново без ручной правки списка.

### Этап 2. Настольная оболочка и игровой запуск

1. Создать отдельный адаптер Electron, не переписывая HTML/WebGL2 игры и `shared/`.
2. Выполнить загрузку локальных файлов без зависимости от веб-адреса GitHub Pages; закрыть произвольную навигацию и `window.open`, отключить `nodeIntegration`, включить `contextIsolation` и `sandbox`, ограничить IPC.
3. Проложить относительные пути шейдеров, ассетов, звуков; устранить критические CDN-зависимости только в упаковке, не изменяя защищённые эталоны.
4. Управление: клавиатура/мышь и контроллер, пауза, полный экран, корректный курсор, плавный возврат в главный мир/каталог. Мобильные интерфейсы в исходниках не ломать.
5. Хранить прогресс в пользовательском каталоге приложения, предусмотреть миграцию форматов сохранений и резервное восстановление. Steam Cloud — отдельный необязательный этап после выбора единого формата.
6. Проверить производительность Three.js/GLSL, переключение между играми, аудиофокус, закрытие процесса и повторное открытие.

**Готовность:** пользователь устанавливает приложение и полностью проходит хотя бы одну игру без браузера и интернета.

### Этап 3. Автосборка GitHub → Steam-ready пакет

1. После изменения игр в `main` GitHub Actions определяет затронутые каталоги, собирает карту зависимостей, версии и список изменившихся ресурсов.
2. Проверяет целостность пакета и обязательные ограничения: реально существующие файлы, локальная загрузка без 404, права на ассеты, неизменность принятых оригиналов, обязательные правила и зелёный общий бот-проходчик там, где он внедрён.
3. Пересобирает только затронутые части, где это возможно, и создаёт цельный Windows-пакет Electron с локальными играми.
4. Формирует предсказуемую версию `appVersion + catalogVersion + Git SHA`; исключает из пакета приватные ключи, исходные секреты, служебные данные и лишние большие дубли.
5. Сохраняет готовый бинарный артефакт CI; при ошибке сборки сохраняет прежнюю публичную версию, не вставляет в релиз поломанную игру.
6. GitHub Actions не должен раскрывать секреты на PR из форков. Загрузка в Steam разрешена только из доверенного окружения и по допустимым правам.

**Готовность:** новую допущенную игру можно добавить коммитом, и она автоматически появляется в новой сборке без ручного вмешательства в каталог.

### Этап 4. SteamPipe и безопасная доставка

1. Подготовить Steamworks SDK ContentBuilder/SteamCMD, настройки AppID/DepotID, launch options, depot-папки и игнорирование лишних файлов.
2. Создать отдельный аккаунт/учётные данные сборщика с минимально нужными правами; ключи и Steam Guard не хранить в git. Авторизовать CI безопасным способом, предусмотренным Steamworks.
3. Автоматически выгружать допущенный билд в **закрытую beta-ветку** Steam; применять `SetLive` только к beta-ветке, если разрешает конфигурация.
4. В Steam-клиенте проверять запуск и наличие всех файлов: игры запускаются из установленного depot, не с GitHub Pages.
5. После успешной проверки издатель выставляет нужный билд публичным в **Steamworks App Admin**. Не выдавать beta-аплоад за релиз для всех.
6. Для критических ошибок оставить предыдущий рабочий Steam-билд и процедуру отката.

**Готовность:** новая игра попадает в Steam beta автоматически после допуска, а после штатной публикации публичного билда доступна игрокам через обновление Steam.

### Этап 5. Публикация и дальнейшая эксплуатация

1. Оформить страницу Steam: название, описание живой коллекции игр, скриншоты настоящего геймплея, трейлер, системные требования, язык, политика обработки данных.
2. Проверить содержание и права каждой игры, возрастные/контентные описания и точность заявлений об ИИ.
3. Пройти ревью страницы и приложения; выпустить первоначальную версию через Steamworks, не объявляя публикацию до фактического доступа покупателям.
4. Новое содержимое из GitHub выпускать пакетными обновлениями Steam с кратким списком изменений; менять Content Survey/страницу при значительном расширении содержания.
5. В дальнейшем: достижения, Steam Cloud, управление контроллером/Steam Deck, Linux/macOS — только после стабильного Windows-релиза, без вмешательства в принятые версии веб-игр.

## 5. Неизменные условия

- Разработка **не начинается с нуля**; использовать текущие игры, 7 движков, общий каталог и `shared/`.
- Источники игровых компонентов — только разрешённые эталоны и подтверждённые игры Claude по `META_GAMES_SOURCE_ALLOWLIST.md`; это **не заменяет проверку прав на коммерческое распространение** всех ассетов и зависимостей.
- Новые игры Claude становятся эталонами кода/ассетов согласно существующим правилам, но **попадают в Steam только после отдельного Steam-ready допуска**.
- Сохранить исходные рабочие сайты, Playgama и все принятые версии. Не трогать защищённый `META_GAMES_PLATFORM.md`, каркас бота и сторожа без предусмотренного разрешения.
- **Не трогать Netlify и пять существующих автозадач ChatGPT.**
- Соблюдать деление ролей из основной цели: Claude проектирует защищённый каркас и контракт, ChatGPT реализует разрешённые компоненты и интеграцию.
- Не обещать автоматическую доставку игроку по факту git push; источником истины для установленной Steam-версии является **опубликованный Steam build/depot**.

## 6. Приёмка цели

Цель достигнута, когда META GAMES официально доступна в магазине Steam и новая игра, добавленная в `main`, без ручного редактирования каталога попадает в проверенную Steam-сборку, далее в Steam beta и после официального переключения публичного билда появляется внутри приложения у пользователей Steam. Старые игры, сохранения и принятые оригиналы остаются рабочими.

**Отдельная публикация каждой новой игры в магазине Steam этой целью не предусмотрена.**
