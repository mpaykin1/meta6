# META GAMES — подробный план MCP-фабрики игр, общего склада и бота-игрока

**Решение владельца: 06.11.2026. Статус: цель и дорожная карта, не утверждение о готовой реализации.**

Главная цель: **любая авторизованная нейросеть подключается по MCP к META GAMES, получает разрешённые игровые детали, собирает оригинальную полноценную игру, улучшает графику и механику, запускает реального бота-игрока, самостоятельно исправляет обнаруженные ошибки, публикует допущенный результат и пополняет общий склад.** Улучшения общей детали автоматически становятся доступны всем играм, использующим эту деталь, без разрушения принятых оригиналов.

Соблюдать: [META_GAMES_PLATFORM.md](META_GAMES_PLATFORM.md) (особенно §§1–13), [META_GAMES_SOURCE_ALLOWLIST.md](../06-rabota-ii-s-kodom/META_GAMES_SOURCE_ALLOWLIST.md), [RULES_CHECKLIST.md](RULES_CHECKLIST.md), [CONTRACT.md](../../scripts/meta-bot/CONTRACT.md), [CROSS_PLATFORM_GOAL.md](CROSS_PLATFORM_GOAL.md), [AGENTS.md](../../AGENTS.md). Настоящий план дополняет, а не меняет защищённые файлы и ограничения. **MCP — Model Context Protocol** (не отдельный игровой движок).

## 1. Конечный пользовательский сценарий

1. Claude, ChatGPT, Codex или другой MCP-клиент подключается к публичному endpoint META GAMES и узнаёт доступные инструменты, их версии, права и лимиты.
2. Агент формулирует замысел (жанр, мир, история, правила, устройства, атмосфера, требуемые FPS), получает реестр эталонов и каталог переиспользуемых компонентов **с точными источниками**.
3. Агент запрашивает у семи движков World_server композицию сюжета, драматургии, механик, физики, визуала/GLSL, онбординга и расчёта (если применимо); фиксирует входы/выходы, seed и правила неповторения.
4. Агент выбирает уже существующие модели, звуки, шейдеры, анимации, код и целые подсистемы из `shared/`. Новые компоненты и улучшения допустимы **на основе разрешённых эталонов**. Не заимствовать игровые ассеты и код из посторонних игр или интернета без отдельного разрешения владельца.
5. Конструктор создаёт **новую рабочую HTML/WebGL-игру**, а не иллюстрацию, промпт, ссылку на чужой сайт или неподвижную сцену. Игрок может управлять персонажем, взаимодействовать с миром, достичь цели, проиграть и выиграть.
6. Игра запускается в изолированной среде; бот через настоящий браузер **играет как человек** (тапы, свайпы, джойстик, клавиши), проходит все уровни на мобильном и десктопном экранах. Он не телепортируется, не изменяет HP и не вызывает игровые методы для прохождения.
7. При ошибке агент получает точное наблюдение, исправляет **только разрешённую рабочую копию**, повторно собирает и запускает бота. Цикл повторяется в пределах бюджета и числа попыток; непроходимый результат не публикуется.
8. Пройденная проверку игра попадает в GitHub и каталог META GAMES, а её **подтверждённые оригинальные компоненты** — в общий реестр. Для новых игр Claude правило эталонности применяется автоматически по allowlist; для остальных авторов — только по действующим разрешениям.
9. Если общий компонент улучшен, сборщик находит все зависимые игры, обновляет их **версии-кандидаты**, проверяет ботом и публикует только успешные обновления. Принятые оригиналы и старые рабочие версии остаются доступны.
10. Владелец играет и говорит «нравится» / «не нравится». Только владелец присваивает художественный OWNER PASS; зелёный бот означает техническую проходимость, но не художественное принятие.

## 2. Архитектура

```text
Claude / ChatGPT / Codex / другие MCP-клиенты
                     |
       HTTPS MCP Gateway (auth, rate limits)
                     |
       MCP tools + jobs + permissions
                     |
   +-----------------+------------------+
   |                 |                  |
каталог эталонов   7 движков         GitHub meta6
   |              World_server        (ветки/PR)
   +-----------------+------------------+
                     |
          Composer / Game Builder
                     |
        HTML + JS + WebGL2 + GLSL
                     |
          Sandbox + Playwright bot
                     |
         Fix -> rebuild -> replay
                     |
        Rights / quality / owner gates
                     |
      shared/ + games/ + catalog
                     |
      Web / Android / Steam candidates
```

**Разделение ответственности:** World_server — сервер MCP, orchestration и семь движков; `meta6` — исходники игр, защищённые эталоны, `shared/`, бот, каталог, CI и опубликованный веб-портал. MCP не должен обходить GitHub guard или изменять защищённые оригиналы.

## 3. MCP API: инструменты и контракты

Сначала инвентаризировать **реально существующие** MCP-инструменты Render и их schemas; не объявлять новые endpoints уже работающими. Сохранить совместимость существующих восьми публичных инструментов, если они доступны. Добавлять версионированные инструменты по мере готовности:

| Группа | Предлагаемый инструмент | Действие / результат |
|---|---|---|
| Discovery | `platform.capabilities` | версии API, доступные engines, права клиента, лимиты |
| Discovery | `games.list`, `games.inspect` | существующие игры, entrypoint, версии, зависимости, статусы |
| Assets | `assets.search`, `assets.inspect` | разрешённые ассеты и код с source SHA, правами, ценой FPS, превью |
| Assets | `assets.dependencies` | граф зависимостей shared-компонента и затронутых игр |
| Planning | `game.plan` | оригинальный замысел, outputs семи движков, seed, требования |
| Build | `game.create`, `game.revise` | асинхронное создание / исправление в отдельной ветке |
| Graphics | `graphics.enhance` | управляемое улучшение шейдеров, освещения, FX, LOD и моделей |
| Bot | `bot.play`, `bot.observe` | запуск реального игрока, уровни, действия, причины провала |
| Quality | `game.validate` | права, качество, правила, performance, безопасность, целостность |
| Lifecycle | `jobs.get`, `jobs.cancel` | состояние длительных операций, тайм-ауты и отмена |
| Publish | `game.propose`, `game.release` | PR, условия допуска, публикация по разрешённым правилам |
| Shared | `shared.propose`, `shared.promote` | безопасное продвижение улучшения в общий склад |

Все записи — **явные инструменты с разграниченными правами**; чтение доступно гостевым клиентам в рамках политики, изменение только авторизованным агентам. У каждой мутации: `requestId` для идемпотентности, `jobId`, `sourceCommit`, `targetBranch`, `actor`, `allowedPaths`, `artifactManifest`, `status` и machine-readable errors. Долгие операции возвращают job, а не блокируют HTTP. Никаких произвольных команд shell, открытых токенов GitHub, записи в `main` или вызова сторонних URL от непроверенного клиента.

## 4. Общий склад и происхождение каждого компонента

1. Провести инвентаризацию **только фактического кода** в пяти исходных эталонах и подтверждённых играх Claude. Игры Claude после загрузки в `meta6` становятся эталонами собственного оригинального кода/ассетов автоматически, но сторонние элементы без прав исключаются. Не переносить остальные артефакты Claude без отдельного слова владельца, пока действует пауза.
2. Разобрать склад на `shared/heroes`, `enemies`, `weapons`, `bosses`, `weather`, `fx`, `audio`, `camera`, `controls`, `ui`, `world`, `models`, `story`, `save`.
3. У каждого компонента `id`, `version`, `kind`, `entry`, `sourceGame`, `sourcePath`, `sourceCommit`, `authorType`, `rightsStatus`, `reuseAllowed`, `license`, `dependencies`, `consumers`, `renderCost`, `acceptedByOwner`, `preview`, `checksum`, `compatibility`.
4. Индексировать фрагменты кода **по семантике и API**, а не только по имени файла: movement, collision, combat, camera, inventory, enemy AI, procedural terrain, fog, particles, shaders, audio, quest, persistence. Доступ агенту через MCP search/inspect.
5. Сначала искать готовый компонент. Если его нет — расширять существующий разрешённый компонент; новый код регистрировать с паспортом и источником. Изменять эталонный оригинал запрещено.
6. Общий импорт через версионированные зависимости (например `@meta/shared/fx/fog@1.3.0` как **логический идентификатор**, не обязательно npm-пакет). В веб-сборке разрешённые файлы физически едины; в офлайн-пакете можно копировать **сборочные артефакты**, не создавая независимые исходные форки.
7. Сначала переводить игры на shared-адаптеры по одной; сравнивать поведение, графику, звук и FPS с принятой версией. Не удалять оригиналы, пока владелец не разрешил.
8. Граф зависимостей позволяет выявлять устаревшие игры и автоматически предлагать обновления с обратимой миграцией.

## 5. Графика: улучшать, усложнять, не разрушать

Разрешённые преобразования: новые комбинации существующих моделей и материалов, увеличение геометрической детализации, улучшение UV/текстур, скелетной анимации, шейдеров GLSL ES 3.0, PBR-освещения, динамических теней, volumetric fog, погодных систем, bloom, tone mapping, отражений, воды, огня, частиц, LOD, GPU instancing, occlusion/frustum/backface culling, оптимизация чанков и текстур. Новые оригинальные процедурные элементы допускаются в рамках разрешённого исходного материала и действующих правил.

**Качество измеряется в игре, а не по картинке:** художественная цель, читаемость, взаимодействие, FPS и память, размер сборки, mobile GPU, контраст, отзывчивость управления, сохранение прогресса. Для каждого графического изменения: до/после в идентичной игровой сцене, кадры из браузера, производительность на одинаковом устройстве, отсутствие регрессий. При ухудшении — уменьшать эффект/использовать fallback, а не публиковать красивый, но непроходимый кадр.

Четыре слоя сцены: глубокий фон, средний план, ближний план, экранный слой. Управлять бюджетом по каждому слою; не рисовать невидимое, не создавать тяжёлые эффекты без пользы. Не менять одобренный художественный образ без OWNER PASS.

## 6. Бот-игрок и автоматическое исправление

Использовать **существующий защищённый каркас Claude** `scripts/meta-bot/` и его `CONTRACT.md`; не переписывать `core.mjs`, `checks.mjs`, `input.mjs`, `server.mjs`, `run.mjs`, `selftest.mjs`, `fixture/`, `template/`, `.github/workflows/meta-bot.yml`. Если нужны новые возможности ядра — отдельное согласованное изменение Claude.

Для каждой игры агент добавляет **только** `games/<game>/bot-adapter.js` (read-only `window.__META_BOT__`), `bot-strategy.mjs`, `bot.json` по действующему шаблону. Бот получает сведения о состоянии, но не может менять состояние. Действия — только пользовательские события: клавиатура, мышь, тач, джойстик, прыжок. Проверять **каждый уровень**, реальное достижение цели, смерть/рестарт, тупики, коллизии, переходы, два разных seed, отсутствие консольных ошибок, ЧИСТЫЙ ЭКРАН, ПОСТЕПЕННО, БЕЗ ПОВТОРОВ, FIX, FPS, мобильное управление (390×844) и desktop.

Цикл восстановления:
```text
bot FAIL -> reproducible seed + input trace + error classification
         -> locate game/shared dependency -> minimal candidate fix
         -> rebuild -> bot replays failed level -> full campaign replay
         -> regression runs for dependent games -> PASS or rollback
```
Классы ошибок: JS/WebGL exception, asset 404, lost input, wall clipping, stuck, unreachable goal, false victory, softlock, level skip, bad camera, FPS collapse, broken save, bad audio. Агент обязан исправлять в рабочей ветке и повторять прогон; при исчерпании лимита помечать `BLOCKED`, сохранять последнюю исправную версию, не выдавать FAIL за PASS. Бот не имеет права подделывать результаты или читать/менять игровые внутренние переменные, кроме предусмотренного read-only контракта.

## 7. Взаимное улучшение всех игр

- Каждое улучшение классифицируется как **локальное** (одна игра) либо **общее** (shared-компонент).
- Общее улучшение оформляется как новая совместимая версия shared-компонента; граф зависимостей находит всех потребителей.
- Для каждого потребителя строится отдельный кандидат, запускается бот и сравнение FPS/визуала/управления/сохранений.
- Успешные кандидаты получают обновление версии компонента. Неуспешные остаются на предыдущей версии и ставятся в очередь исправлений. **Нельзя глобально подменять ассет так, чтобы сломать сразу все игры.**
- Локальное улучшение, пригодное другим играм, извлекается в `shared/` после проверки прав, паспорта и независимой проверки; так каждый мир помогает другим.
- Приоритет очереди: блокирующие баги → непроходимость → нарушения универсальных правил → FPS/управление → сюжет/звук/графика → новые механики. **Одна игра за раз**, очередь `docs/meta-bot-queue.md` по основной цели; не создавать конкурирующие очереди.
- Не смешивать глобальные игровые улучшения с публикацией в Steam/Google Play: для каждого канала свой допуск и пакет.

## 8. Безопасность и допуск

**MCP публичный для чтения, но не для неограниченной записи.** HTTPS, OAuth/токены с scopes (`read:catalog`, `create:game`, `propose:shared`, `run:bot`, `publish:web`), квоты, лимиты расходов/времени, аудит операций, секреты только в защищённом окружении. Любой пользовательский prompt и код игры — недоверенные данные; защита от prompt injection, SSRF, traversal, ZIP-slip, вредоносного HTML/JS, запуска кода с привилегиями CI. Изолированный браузер и минимальные permissions; недоверенный PR не получает publish secrets. GitHub guard — обязательный.

**Гейты:** `SOURCE_ALLOWED` → `RIGHTS_VERIFIED` → `BUILD_PASS` → `BROWSER_PASS` → `BOT_PASS` → `RULES_PASS` → `PERF_PASS` → `WEB_RELEASE_READY`. `OWNER_PASS` отдельно и только по решению владельца. `STORE_READY` отдельно после проверки требований Steam/Google Play. Не выставлять статусы автоматически по факту создания файлов или прохождения одного теста.

## 9. Этапы внедрения (в порядке зависимостей)

| Этап | Конкретная работа | Критерий готовности |
|---|---|---|
| **0. Инвентаризация** | Сверить `meta6/main`, `World_server/master`, Render MCP, семь движков, восемь существующих инструментов, текущие PR, защищённые пути, список игр и статус бота | Матрица **реально работающих** функций без вымышленных PASS |
| **1. MCP Gateway** | HTTPS MCP endpoint, capabilities, auth/scopes, схемы ошибок, версии, jobs, read-only каталог | Внешний MCP-клиент обнаруживает инструменты и читает реальный каталог |
| **2. Склад** | Паспортировать исходники и права, дедупликация, семантический поиск фрагментов, dependency graph, версионированный shared | Агент находит нужную функцию/ассет и получает точный SHA/путь; эталоны неизменны |
| **3. Семь движков** | Вызвать реальные движки World_server, нормализовать outputs, seed и неповторение, контракт с renderer | Один запрос возвращает валидный игровой план, пригодный для сборки |
| **4. Конструктор** | Из outputs движков и shared собрать полноценный HTML/WebGL runtime, mobile/desktop input, физику, выигрыш/проигрыш, ассеты, save | Новая игра запускается локально без ошибок и имеет достижимую концовку |
| **5. Бот** | Адаптеры, стратегии и конфиги для каждой игры; браузерный проход на desktop/mobile, два seed, проверка правил | Бот реально проходит все уровни, без читов и ложных PASS |
| **6. Самоисправление** | Локализация сбоя, минимальный патч, повторный бот, лимиты, rollback, безопасные PR | Один намеренно воспроизводимый сбой исправляется без изменения оригинала |
| **7. Взаимные улучшения** | dependency graph → кандидаты всех игр → регрессионные прогоны → совместимые версии shared | Одно улучшение общего компонента видно в нескольких играх, старые версии сохранены |
| **8. Графика** | Улучшения GLSL/FX/LOD/моделей по слоям, профили устройств, FPS-бюджеты, fallback | Заметное улучшение в настоящем геймплее без критического падения FPS |
| **9. Веб-публикация** | PR, guard, release gate, каталог, откат, URL опубликованной игры | MCP-клиент создаёт и доводит игру до реально работающего URL |
| **10. Store channels** | Пакеты Android/Windows из тех же исходников, offline assets, реклама выключена в Steam, отдельные ревью | Установленные сборки работают; магазины публикуются только после их допуска |

**Межэтапный приоритет:** сначала довести до конца уже начатые работы по боту и текущим играм; не объявлять весь конвейер готовым по одному успешному примеру.

## 10. Минимальный сквозной сценарий приёмки

Авторизованный Claude/ChatGPT через MCP просит: «Создай новую 3D-игру с туманом, живым миром, врагом, целью и концовкой; используй только разрешённые эталоны; улучши свет». Сервер показывает использованные `shared` компоненты с источниками, вызывает семь движков, создаёт новую папку `games/<new-id>/` в отдельной ветке и реальный WebGL runtime. Бот дважды проходит все уровни на мобильном и ПК; при сбое агент чинит, пересобирает и перепроходит. После всех обязательных гейтов игра доступна на сайте META GAMES, а её разрешённые компоненты доступны для следующих игр. Вторая игра использует улучшенный общий эффект; после обновления эффекта обе игры получают проверенные версии, без изменения принятых оригиналов.

## 11. Что не делать

Не переписывать защищённую цель или ядро бота Claude; не удалять/переносить исходники из артефактов без разрешения; не использовать неразрешённых доноров; не выдавать CI-сборку за опубликованную игру; не разрешать агентам писать напрямую в `main` или менять чужие проекты; не создавать платные обязательные зависимости; не трогать Netlify и пять автозадач без отдельного разрешения; не утверждать, что бот прошёл уровень, если он лишь загрузил страницу.

## 12. Действие для Claude и ChatGPT

Открыть этот документ вместе с основной целью и контрактом бота; выбрать **первый незавершённый этап**, проверить фактическое состояние исходников и MCP, реализовать только недостающую часть в разрешённых файлах, запустить реальные проверки, исправить ошибки, открыть PR и слить при соблюдении guard и гейтов. Отдельно фиксировать статусы `implemented`, `verified`, `published` — не смешивать их. План считается завершённым только после сквозного сценария §10.
