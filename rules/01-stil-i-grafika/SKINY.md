# СКИНЫ — как превратить примитивного героя в детального (обязательно, все игры, 09.11.2026)

Решение владельца 09.11.2026: персонажи должны выглядеть круто **только за счёт скина**: примитивная фигура (блокинг) остаётся, на неё надевается пакет ассетов — текстуры, накладные детали и анимированные 2D / 2.5D элементы. Пакет делает ChatGPT строго по этому файлу. Claude только проверяет и забирает.

Учебная игра: [games/skin-trainer/](../../games/skin-trainer/index.html) (артефакт владельца `6caf418d-a99f-4a40-afee-7a3098abeeed`).
Первый эскиз: [reference/skins/rusty-robot.png](../../reference/skins/rusty-robot.png) — «ржавый робот».

## 0. Термины (весь конвейер скина)

| Этап | Что это | Что сдаёт ChatGPT |
|---|---|---|
| Блокинг / базовый меш | грубая фигура из примитивов: силуэт и пропорции | ничего — блокинг уже есть в игре, его **не менять**; можно скрыть части через `hideBase` и заменить своими 3D-деталями |
| UV-развёртка | как плоская картинка ложится на объём | для каждой текстуры — `uv`: `box6` (6 граней куба), `cyl` (обёртка цилиндра + крышки), `sphere` (равнопромежуточная), `plane` |
| Текстурирование | цвет, ржавчина, трещины, заклёпки, краска | `textures/*.png` (albedo) |
| Запекание (baking) | тени, впадины, мелкий рельеф «нарисованы» в текстуру, чтобы простая модель выглядела сложной | AO и грани **запечены в albedo**; отдельно `*_emit.png` — карта свечения |
| Шейдинг | как поверхность реагирует на свет | `materials` в skin.json: `rough`, `metal`, `emissive`, `emissiveMap`, `blend` |
| Анимированные детали | шестерни, провода, дуги, лампы, пар | `parts` + `sheets/*.png` (флипбуки) |

## 1. Формат пакета — ZIP `meta6-skin/1`

Сдаётся **ZIP и та же распакованная папка** (байт в байт) в `skins/packs/<имя>.zip` и `skins/packs/<имя>/`:

```
<имя>/
  skin.json        манифест (схема ниже)
  reference.png    эскиз владельца (копия)
  preview.png      скрин скина в учебной игре: спереди, сбоку, сзади (3 кадра в ряд)
  textures/        albedo + *_emit.png, 64/128/256 px, степень двойки, пиксель-арт
  parts/           накладные детали (пластины, панели, линзы, болты) — PNG с прозрачностью
  sheets/          флипбуки: горизонтальная полоса кадров одинакового размера
  README.md        5–10 строк: что внутри
```
Другие типы файлов запрещены. Весь пакет ≤ 3 МБ, картинок ≤ 60.

### skin.json
```json
{
  "format": "meta6-skin/1",
  "name": "rusty-robot",
  "reference": "reference.png",
  "palette": ["#c8551e", "..."],
  "hideBase": ["body", "armL"],
  "materials": { "rust": {"rough":0.9,"metal":0.3}, "glow": {"emissive":"#ffb040","blend":"additive"} },
  "textures": [ {"id":"head_rust","file":"textures/head_rust.png","emit":"textures/head_rust_emit.png","uv":"sphere","material":"rust","apply":"head"} ],
  "parts": [
    {"id":"chest_gear","kind":"gear","layer":"2.5d","bone":"body","file":"parts/gear.png",
     "size":[0.32,0.32],"pivot":[0.5,0.5],"offset":[0.12,0.15,-0.31],"rotation":[0,0,0],"depth":3,
     "material":"rust",
     "anim":[{"type":"rotate","axis":"z","freq":0.35,"phase":0.2,"speedLink":1.5}]}
  ]
}
```

**Кости (`bone`)** учебной игры: `root, body, head, armL, armR, legL, legR, antenna`. Перед героя = **−Z**, рост ≈ 2.1, единицы — метры сцены. Плечо/бедро — точка вращения конечности, конечность висит вниз (−Y).

**Слои (`layer`):**
- `3d` — объёмная деталь из примитива (`primitive`: `box | cylinder | sphere | torus`, `dims`) с текстурой и UV;
- `2.5d` — плоская деталь со стопкой `depth` 1–5 копий по глубине (объём из плоских слоёв, параллакс);
- `2d` — билборд, всегда повёрнут к камере (дуги, искры, ореолы, угольки).

**Анимации (`anim` — массив, слои складываются):**
`rotate` (шестерни), `bob` (парение), `swing` (качание с инерцией от движения героя), `chain` (провод из `segments` звеньев, волна идёт по звеньям с задержкой `lag`), `pulse` (свечение дышит), `flicker` (лампа мерцает), `flipbook` (`frames`, `fps`, `duty` — доля времени видимости, для дуг), `orbit` (кружит вокруг точки), `flap` (оторванная пластина дрожит).
Общие поля: `freq` 0.05–12 Гц, `amp`, `phase` 0–1, `speedLink` (насколько ускоряется при беге), `pulseLink` (реакция на вспышку `pulse` игры), `inertia` (запаздывание за поворотом героя).

## 2. Жёсткие требования (каждое проверяет валидатор)

| ID | Требование |
|---|---|
| S1 | ZIP и папка совпадают байт в байт; `name` = имя папки; `format` = `meta6-skin/1` |
| S2 | Все файлы из skin.json существуют; лишних картинок нет (кроме reference/preview) |
| S3 | PNG RGBA, стороны — степень двойки ≤ 256; у parts/sheets углы прозрачные |
| S4 | Пиксель-арт: фильтр nearest, ≤ 48 цветов на картинку, полупрозрачных пикселей ≤ 5 % (кроме `blend:additive`) |
| S5 | Палитра 6–16 цветов, снята с эскиза; ≥ 90 % непрозрачных пикселей обычных картинок — в пределах 28 (RGB) от цвета палитры |
| S6 | Деталей ≥ 30, анимированных ≥ 24, разных `kind` ≥ 8; слоёв: `3d` ≥ 6, `2.5d` ≥ 8, `2d` ≥ 6 |
| S7 | Обязательные `kind` с эскиза: `plate` (рваная ржавая пластина), `gear`, `cable`, `arc` (электрическая дуга), `slit` (светящиеся щели), `core` (светящаяся колба в груди), `lens` (глаз-кольцо), `orb` (парящий огонёк над головой), `bolt`, `panel` (пластина с полосами), `piston` |
| S8 | Каждая кость `body, head, armL, armR, legL, legR` — ≥ 2 детали; сзади (offset z > 0) ≥ 4 детали — герой красив со спины и сбоку |
| S9 | `rotate` ≥ 3, `chain` ≥ 2 (по 3–6 звеньев), `flipbook` ≥ 3 (по ≥ 6 кадров), `speedLink>0` ≥ 4, `pulseLink>0` ≥ 3, `additive` ≥ 5 |
| S10 | Ни одна деталь не движется синхронно с другой: пары (`freq`,`phase`) уникальны у ≥ 90 % анимаций |
| S11 | Каждая скрытая кость из `hideBase` получает ≥ 1 деталь `3d` |
| S12 | Флипбук: ширина = `frames` × ширина кадра; кадры действительно разные (нет одинаковых подряд) |

## 3. Движок, валидатор, учебная игра

- **Движок** `skins/runtime/skin-runtime.js` (один на все игры): `SkinRuntime.load(url, THREE) → skin`, `skin.apply(RIG)`, `skin.update(t, dt, {speed, pulse, lean, walk})`. Учебная игра уже вызывает его и открывается со скином так: `games/skin-trainer/?skin=../../skins/packs/<имя>/`. Без `?skin` игра — как оригинал.
- Текстуры грузятся один раз; в кадре — только трансформы, uniform-ы и смещение UV флипбука. Никаких попиксельных циклов на CPU, никаких новых объектов в кадре, без теней. Деталей вне экрана не считать (ВИДИМО И ЭКОНОМНО). Добавка скина ≤ 60 draw calls, FPS на телефоне не ниже оригинала более чем на 10 %.
- **Валидатор** `scripts/skins/validate-skin-pack.mjs <папка>` — проверяет S1–S12, печатает нарушенные ID. **Ловушки** `scripts/skins/mutate-skin-pack.mjs` (КОНТУР К5): ≥ 6 испорченных копий, включая обман (папка изменена, ZIP старый; флипбук заявлен 8 кадров, а нарисовано 2) — валидатор обязан упасть на каждой.
- Workflow `.github/workflows/skin-pack.yml` гоняет валидатор и ловушки на каждом PR с `skins/**`, плюс headless Chrome: игра со скином открывается без ошибок консоли и делает `preview.png`.

## 4. Как ChatGPT делает скин (порядок, не менять)

1. **Разобрать эскиз**: таблица «деталь — kind — кость — слой — анимация — цвет» (в README пакета). Силуэт, материал, повреждения, механика, свечение, 2D-эффекты.
2. **Палитра** — снять с эскиза.
3. **Текстуры + запекание**: ржавчина, трещины, сколы, заклёпки; тени и грани нарисованы в картинке.
4. **Детали** parts/ и **флипбуки** sheets/ — пиксель-арт, как на эскизе.
5. **skin.json** — раскладка по костям, анимации со сдвигом фаз (волна по телу, не всё разом).
6. Валидатор → зелёный. Скрины спереди/сбоку/сзади → `preview.png`. Сравнить с эскизом глазами; не похоже — переделать до сдачи.

## 5. Приёмка
Ссылка поиграть + зелёный прогон + ZIP. «Нравится / не нравится» ставит только владелец. Нашёл ошибку → исправь сам, потом сообщай. Каждое «готово» — со ссылкой, SHA или прогоном Actions.

## 6. ПЛАН НА БУДУЩЕЕ — скины для всех игр автоматически (решение владельца 09.11.2026)

Статус: **НЕ НАЧИНАТЬ**, пока владелец не сказал «нравится» про скин «ржавый робот» в учебной игре. Запускает только владелец через Claude.

1. **Сначала эталон.** Ржавый робот принят владельцем → «надеватель» `skin-runtime.js`, валидатор и ловушки считаются проверенными. Сырые инструменты на все игры не переносить.
2. **Скелет героя в каждой игре.** В каждую игру добавить объект `RIG` (кости и базовые меши, как в `games/skin-trainer`) и подключение `?skin=…`. Без `?skin` игра — байт в байт как была (проверка в CI).
3. **Эскиз на каждого героя** в `reference/skins/<игра>.png`. Источник: эскиз владельца или эскиз, который ChatGPT нарисовал в стиле игры и владелец одобрил. Скины разных игр не должны быть похожи друг на друга.
4. **Автозадача:** один запуск = одна игра = один пакет `skins/packs/<игра>-<герой>/`, ветка `lab/skin-<игра>`, зелёный skin-pack, ссылка поиграть, карточка LAB_QUEUE. Очередь игр — по списку `list_games` витрины, не по памяти.
5. **Разные виды героев:** воксельный, 2D-спрайт, 3D-примитивы — для каждого вида отдельный адаптер в `skin-runtime.js`, формат пакета общий (`meta6-skin/1`).
6. **Красиво или нет — решает только владелец** («нравится / не нравится»). Валидатор проверяет правила, не вкус. Забирает в `meta6` только Claude.

## 7. ПО ЭТАПАМ — скин делается маленькими шагами (решение владельца 09.11.2026)

Причина: «нарисовать всё и надеть» сразу — слишком большая задача, ChatGPT делает формально, но не похоже. Поэтому скин собирается **по 8 этапам**. Один этап = одна сессия ≤ 1 часа = один коммит.

**Как работать на каждом этапе (одинаково всегда):**
1. Открыть `skins/packs/<имя>/STAGE.md` — там номер текущего этапа и что принято раньше. Нет файла — этап 0.
2. Сделать **только этот этап**. Чужие этапы не трогать, принятое не переделывать.
3. Собрать картинку сравнения `skins/packs/<имя>/stages/<N>.png`: **слева кусок эскиза, справа результат** этапа (на герое в игре или на сером фоне).
4. Валидатор с флагом `--stage N` (проверяет только то, что уже должно быть) — зелёный.
5. Записать в STAGE.md: «этап N сделан, SHA, прогон, картинка» и **ОСТАНОВИТЬСЯ**.
6. **Приёмку этапа делает Claude** (решение владельца 09.11.2026), не владелец: Claude пишет в PR комментарий `СКИН-ПРОВЕРКА: этап N принят` или `СКИН-ПРОВЕРКА: этап N — исправить: …`. Следующий этап — только после «принят». «Исправить» — переделать этот же этап по замечаниям. Владелец смотрит только итог после этапа 7.

**Критерий приёмки:** не пиксельное совпадение, а **по смыслу максимально похоже на эскиз**: те же цвета и материалы, тот же силуэт, те же детали на тех же местах, то же настроение.

| № | Этап | Что сдать | Как понять, что правильно |
|---|---|---|---|
| 0 | Разбор эскиза | таблица всех деталей (часть тела — что это — цвет — двигается ли) + палитра 6–16 цветов с образцами | на картинке: эскиз со стрелками-номерами → таблица; цвета палитры рядом с теми местами эскиза, откуда сняты |
| 1 | Материал | одна пластина ржавчины 64×64 и один кусок тёмной механики 64×64 | рядом с увеличенным куском эскиза — не отличить по цвету и манере; без шума, крупные ровные тона, грань светлая, тень тёмная |
| 2 | Силуэт | броня-пластины на голову, тело, плечи, руки, ноги — **без анимации** | герой спереди/сбоку/сзади рядом с эскизом: силуэт читается за 1 секунду |
| 3 | Механика внутри | шестерни, трубки, поршни, провода, болты — **без анимации** | видны сквозь дыры в пластинах там же, где на эскизе |
| 4 | Свечение | щели, колба, полоски голени, огонёк над головой | светится только это, тёплым оранжевым |
| 5 | Движение механики | вращение шестерён, ход поршней, качание проводов с инерцией | короткое видео/GIF 3 с: всё живёт, но не синхронно, волной |
| 6 | 2D-эффекты | дуги из концов проводов, искры, дым — флипбуки | GIF: дуги бьют коротко, вспышками, из проводов |
| 7 | Реакция и сдача | ускорение от бега, вспышка от `pulse`, вид сзади, FPS, ZIP, полный валидатор S1–S12 | ссылка поиграть + полный зелёный прогон |

Полная проверка S1–S12 — только на этапе 7. На этапах 0–6 валидатор проверяет формат и то, что относится к этапу.
