# БЕЗ РОВНЫХ КРАЁВ — края островов, берега, суши и мира (обязательно, все игры, 13.11.2026)

Решение владельца 13.11.2026 («Остров последнего аптекаря»): «Край слишком ровный. Так быть не должно. Нужно сделать острову красивый край, как в реальности бывает у островов. И красивый цвет воды, как на эскизе».

## Правило

1. **Запрещены** края суши/острова/уровня/плато, которые видны игроку как прямая линия, прямоугольник, скруглённый прямоугольник, ровный круг или идеальная дуга. Также запрещены «обрезанные» края: мир кончается пустой бумагой или пустым фоном без воды, тумана или перехода.
2. **Берег как в природе:** неровный контур с мысами, бухтами и косами на разных масштабах (крупные изгибы + средние + мелкая неровность). Песчаная полоса **разной ширины**, небольшой обрыв или откос к воде, камни и валуны на кромке, 1–5 островков или скал в море рядом.
3. **Вода вокруг острова обязательна.** Цвет с эскиза владельца (Nookvale): бирюзово-синяя глубина `#2f5a66`, `#41707b`, светлая отмель у берега `#6f9c9b` → `#a7b9a0`, пена у кромки `#e8e6d6`, редкие тёплые отблески `#c98d6c`. Переход «отмель → глубина» плавный, по расстоянию до берега. Вдали вода уходит в туман, а не обрывается.
4. **Без однообразных узоров** (правило БЕЗ ПАТТЕРНОВ): контур и вода — на шуме fbm с искривлением координат, а не на сумме синусов и не на повторяющейся текстуре.
5. **Ассеты только из эталонов** (камни, деревья, камыш — генераторы игры). Похожие новые модели не рисовать.
6. **Эталон не менять.** Если ровный край зашит в принятом эталоне, новый берег кладётся поверх в коде игры. Старая вода прячется, суша рисуется заново выше старой. Файлы эталона не трогаются.
7. Ходить можно по всей новой суше, кроме воды. Сюжетные места (причал, дома, дорога) не сдвигаются: отступ берега идёт только наружу.

## Готовый образец (копировать, не переписывать)

`games/ostrov-aptekarya/coast.js` в meta6-lab (https://github.com/mpaykin1/meta6-lab/blob/main/games/ostrov-aptekarya/coast.js) — `createCoast({scene, paint, makers})`:

```js
// 1) Отступ наружу от старого контура: fbm на трёх масштабах + мысы (гауссовы бугры)
let o = .6 + 4.6 * Math.pow(fbm1(s * 9), 1.5) + 2.6 * fbm1(s * 24) + .9 * fbm1(s * 70);
for (const [c, amp, w] of capes) o += amp * Math.exp(-((s - c) ** 2) / (w * w));
// 2) Сглаживание Чайкина ×2 → мягкие природные изгибы без изломов
// 3) Песок = весь контур, трава = контур, сдвинутый внутрь на ширину пляжа .3–1.2 (шум)
// 4) Обрывчик: полоса от песка вниз к воде, землистый цвет; чернильная линия кромки
// 5) Море — кольца от берега наружу, у вершины атрибут aDist (расстояние до берега):
//    цвет отмель→глубина по aDist, пена по aDist<0.6, круги дождя, туман сцены (fog:true)
// 6) Камни makers.rock() на кромке + островки с ёлкой makers.fir()
```

## Проверка перед сдачей (агент делает сам)

1. Скриншоты телефона 390×844 и ПК у **каждого** края мира (север, юг, запад, восток, углы). На каждом снимке берег неровный, есть вода, нет пустого фона.
2. В отчёте ссылки на эти скриншоты (артефакт прогона) — без них правило не выполнено.
3. Бот проходит игру как раньше (берег не перекрыл дорогу, причал, цели).
4. Нашёл ровный край в любой игре МГ/МГЛ — сам исправь по образцу и только потом пиши отчёт. Отчёт «нашёл ровный край» без исправления запрещён.
