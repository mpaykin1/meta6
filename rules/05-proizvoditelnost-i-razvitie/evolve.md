# evolve — универсальная инструкция саморазвития технологий для всех ИИ

**Короткий пароль:** `evolve` (также `GRAF Evolution`). **Публичный адрес:** https://github.com/mpaykin1/meta6/blob/main/evolve.md

## Область действия
Для Claude, ChatGPT, Codex, OpenCode, OpenHuman и других агентов. Ежедневно развивать проверяемые технологии графики и анимации во всех играх, без дублирования задач. Это общий договор координации, **не доказательство запуска планировщика**.

**Обязательные источники каждого цикла:**
- Стандарт: https://github.com/mpaykin1/meta6/blob/main/graf.md
- Живая программа: https://github.com/mpaykin1/World_server/issues/524
- Центральная AKA: https://github.com/mpaykin1/World_server/issues/80
- Контракт конкретной игры, AGENTS.md/CLAUDE.md и актуальные PR.

## Десять направлений
1. 3D→2.5D→2D фабрика персонажей и ассетов с реальными анимациями.
2. Адаптивные гибридные LOD, синхронизация фаз, FPS.
3. Живые реакции мира на события.
4. Независимый визуальный критик по утвержденному эталону.
5. Гибридные существа: 3D тело, 2.5D части, 2D эмоции/эффекты.
6. Версионированный графический геном проверенных рецептов.
7. Контекстная кинематография: свет, туман, камера, цвет.
8. Анимированные разрушения с мобильным бюджетом.
9. Общая лицензированная библиотека ассетов для всех игр.
10. Ограниченные эволюционные A/B эксперименты с независимыми тестами.

## Ежедневный протокол всех агентов
1. Прочитать свежие ссылки, проверить issues, PR, ветки, владельцев задач, блокеры и последний SHA.
2. Не дублировать работу ChatGPT/Codex/Claude/AKA. Занять **один свободный участок** в GitHub; не изменять чужую ветку.
3. Выбрать слабое место, видимое игроку, и проверяемую гипотезу. В первую очередь реализовывать работающий код/ассеты в существующей игре, не заменять задачу планированием.
4. Цикл: АНАЛИЗ → ГИПОТЕЗА → РАЗРАБОТКА → ТЕСТ → СРАВНЕНИЕ → СОХРАНЕНИЕ ОПЫТА → СЛЕДУЮЩИЙ ШАГ. При двух циклах без видимого результата сменить подход.
5. Проверить фактические анимации и 2D/2.5D/3D/hybrid, управление ПК и телефоном, отсутствие регрессий. Сравнить до/после, FPS p50/p95, память, draw calls, WebGL, точный SHA. Не придумывать цифры и результаты тестов.
6. Создать отдельную ветку и PR, приложить ссылки на изменения, скриншоты/видео, измерения и лицензии. Согласовывать интеграцию с владельцем игры и независимыми gate.
7. Обновить #524 и при необходимости #80: количество открытых блокеров в начале отчета, технология, видимое изменение, SHA/PR, тесты, статус, следующий оптимальный шаг. Обеспечить чтение результатов любым ИИ по публичным ссылкам.
8. Технически проверенные рецепты переносить в библиотеку только с версией, лицензией и подтверждением на втором сценарии. Отрицательные эксперименты фиксировать как технические факты, а не пользовательский FAIL.

## Планировщик
**Желаемое расписание:** ежедневно **02:00 Asia/Tbilisi** (согласно последнему прямому редактированию пользователя; оно имеет приоритет над старым 09:00 в тексте). Название: `GRAF Evolution — Daily Research & Development`.

Каждый ИИ сначала проверяет наличие существующей аналогичной задачи и ее владельца. **Не создавать шестую задачу AKA**; предпочтительно использовать/обновить уже существующую автоматизацию или один согласованный внешний Claude-планировщик. Если агент действительно имеет штатный планировщик и пользователь разрешил его создать, включить ежедневный запуск и один тестовый прогон. При отсутствии планировщика допустимо предложить безопасный GitHub Actions workflow, но не создавать неконтролируемый запуск и не заявлять об активном расписании без проверки. Разные ИИ координируются **асинхронно через GitHub**, не через вымышленный прямой чат.

## Неприкосновенные правила
- Сохранять 50/50 **развитие графики / CLEAN_SERVER** в действующей AKA; не отменять актуальные цели выпуска игры и соглашения двух разработчиков.
- Не ломать утвержденные версии, не заменять движок, не обходить CI/review, не мерджить без полномочий.
- Только бесплатные инструменты без платных API/ключей; лицензии проверять для кода и ассетов отдельно; секреты не публиковать.
- Новый игровой тестовый URL только после независимого >85% подтвержденного player-visible gate. **Только владелец решает PASS/FAIL**.
- Отдельно различать PLAN, IMPLEMENTED, TESTED, DEPLOYED и OWNER_ACCEPTED; отсутствие доказательств не равно успеху.

## Проверка запуска
После настройки показать точное расписание, механизм запуска, первый тестовый run, GitHub-ссылку на запись результата и время следующего запуска. Пока этого нет — статус **инструкция опубликована, автоматизация не подтверждена**.
