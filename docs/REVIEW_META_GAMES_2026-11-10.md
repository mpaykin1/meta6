## Что сломано или тормозит (по важности)

### 1. КРИТИЧНО — ночная синхронизация стирала принятую работу — ИСПРАВЛЕНО
`Sync from meta6` делал `rsync --delete`: песочница становилась копией meta6, и всё, что Claude принял в песочнице, но ещё не перенёс в meta6, удалялось. Три синхронизации подряд с одной и той же базой `cb6da0ad` уже откатывали песочницу. Сухой прогон 10.11: следующий запуск удалил бы **109 файлов** — проверки B1 и P1 (`scripts/platform`), станок библиотеки, `scripts/kontur`, ZANYATO.md, BUDUSHEE.md, 4 эталонные игры — и заменил бы витрину `meta-games/index.html`, по которой работает `list_games` (M1). То есть 3 из 7 зелёных пунктов финиша покраснели бы.
**Исправление:** `scripts/lab/sync-from-meta6.sh` переносит только то, что изменилось в meta6 после прошлой синхронизации (база в `.lab-sync-base`); файлы только песочницы не трогаются; если файл меняли обе стороны, остаётся версия песочницы, а путь выводится как конфликт. Нет базы — остановка без изменений. Проверка `scripts/lab/test-sync-from-meta6.sh` (4 ловушки) запускается первым шагом workflow. OSHIBKI №15.

### 2. Пробка из PR — работа не доходит до main
69 открытых PR в песочнице, 35 из них старше 48 часов; за последние 14 часов ни одного слияния, хотя 5 автозадач работают каждый час. Причины:
- принимает только Claude, а у Claude мало токенов, и для каждого PR ему приходится читать длинное описание;
- общие файлы (OSHIBKI.md, LAB_QUEUE.md, ZANYATO.md, `meta-games/index.html`, `shared/index.json`) правят почти все PR, поэтому PR быстро получают конфликты (#200, #204, #205, #190 — `dirty`);
- дубли: эталоны одной и той же игры открыты по 2 раза (Король Пепла #206/#207, Затонувший город #142/#191, ABYSS GLOW #134/#195).
**Решение:** боты A13 (уборщик), A14 (фрагменты вместо общих файлов), A15 (короткая сводка для Claude) — этап 0 плана.
