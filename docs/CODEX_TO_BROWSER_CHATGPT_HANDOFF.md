# Codex → новый обычный браузерный чат ChatGPT

> При подготовке эта редакция сохранена в отдельной
> [ветке для ревью](https://github.com/mpaykin1/meta6/tree/ai/codex/browser-chatgpt-handoff),
> без слияния в `main`. Новые `AGENTS.md` и этот документ доступны по рабочей ветке;
> они не становятся инструкциями `main` до подтверждённого слияния PR. Передавайте
> ссылки с полным SHA из checkpoint. Заменяйте их ссылками на `main` только после
> проверки фактического слияния.

Это постоянное правило владельца для [meta6](https://github.com/mpaykin1/meta6)
и [World_server](https://github.com/mpaykin1/World_server).
Получатель незавершённой работы — **НОВЫЙ ОБЫЧНЫЙ ЧАТ CHATGPT В БРАУЗЕРЕ,
НЕ новый Codex**. Продолжается текущий проект и текущая задача.

## Когда и в каком порядке передавать

1. При признаках приближения лимита токенов, контекста, квоты или времени заранее
   предупредите владельца. Не выдумывайте численный остаток, если он недоступен.
2. Сначала сохраните изменения в отдельной ветке GitHub, создайте или обновите PR.
   Не меняйте напрямую `main` в meta6 или `master` в World_server. Не теряйте код,
   если PR или сеть временно недоступны: сохраните коммит и честно запишите, что
   осталось только локально, что отправлено и какая операция заблокирована.
3. Обновите **существующий** GitHub checkpoint в
   [World_server issue #80](https://github.com/mpaykin1/World_server/issues/80)
   и связанный активный task ledger. Сначала найдите актуальную запись задачи;
   продолжайте её, не заводите конкурирующий checkpoint или новый проект.
4. Подготовьте полноценный готовый промпт для нового обычного браузерного ChatGPT:
   все ссылки, контекст, приоритеты и первые действия должны быть внутри текста.
5. Передайте владельцу прямую ссылку на обновлённую запись checkpoint, прямую
   ссылку на PR и весь готовый промпт, который можно вставить одним действием.
6. Если инструмент действительно умеет создать **обычный браузерный чат ChatGPT**
   и передать контекст, выполните это в рамках разрешённого доступа и сохраните
   ссылку на чат. Не подменяйте его новым Codex или внутренним агентом. Если такого
   инструмента нет, честно укажите ограничение и отдайте готовый текст для вставки.
7. Следующий ChatGPT продолжает текущую работу: использует существующий checkout,
   ветку и зависимости; не начинает проект заново, не повторяет установку и не
   переписывает готовые модули. Устанавливайте только доказанно недостающие
   зависимости, бесплатными средствами. Не создавайте Git worktree без явной
   просьбы владельца. Доступ к GitHub не требует повторной настройки лишь потому,
   что отдельный запрос API завершился ошибкой.
8. Поддерживайте ссылки на это правило в инструкциях обоих репозиториев, чтобы
   следующая сессия могла его обнаружить без памяти чата.
9. **Никогда не назначайте PASS или FAIL самостоятельно. Только владелец оценивает
   результат.** Технические проверки записывайте фактами: команда, полный SHA,
   число тестов, код завершения, ограничения. Анализ успеха или неудачи сохраняйте
   исключительно после явного решения владельца, с его цитатой и ссылкой.

При нехватке ресурсов приоритет неизменен:
**сохранить код → сохранить checkpoint → подготовить продолжение в браузерном
ChatGPT → сообщить владельцу**.

## Что записать в существующий checkpoint

Каждое неизвестное поле отмечайте `UNKNOWN` с причиной. Не заменяйте отсутствующие
сведения предположениями или старым зелёным CI.

- Что Codex действительно успел сделать, а что осталось только планом.
- Что осталось по ТЗ Observer World V5; отдельно уже существующие реализации V6,
  чтобы следующий чат не сделал их заново.
- Конкретные файлы и требуемые изменения; отличайте подтверждённый дефект от
  кандидата для диагностики.
- Репозиторий, базовая ветка/полный SHA, рабочая ветка, **полный commit SHA**, PR.
- Выполненные проверки с командами и результатами; проверки с ошибками;
  отдельно **не запускавшиеся** проверки и причины.
- Оставшиеся баги, блокеры, необходимое разрешение или действие владельца.
- Что делает основной чат ChatGPT и Claude, только если есть свежая ссылка на
  их запись/задачу. Иначе `UNKNOWN`; не утверждайте, что они получили сообщение.
- Как продолжить без повторной установки: checkout, ветка, доступные инструменты,
  существующие зависимости, команды запуска/проверки, необходимые имена переменных
  без значений секретов.
- Последняя рабочая игра: версия, источник/полный SHA, адрес, время и способ
  последней проверки. Разделяйте **адрес из исходников** и **свежепроверенную
  playable-версию**. Если live-доступ заблокирован, так и напишите; HTTP 200 и CI
  сами по себе не доказывают работу игры на устройстве владельца.
- Решение владельца: точная цитата и ссылка либо `UNKNOWN / решение не получено`.
  Решения для графики, музыки, gameplay и разных версий не переносите друг на друга.

Не сохраняйте токены, значения секретов или дамп окружения в checkpoint, промпте
или репозитории. Этот документ — правило и шаблон, а не второй checkpoint.
