# PLAYGAMA RETENTION — как исправлять игры, чтобы их не бросали (обязательно, все игры)

Пароль: `retention`. Читать **перед любой правкой или публикацией игры на Playgama**. Основано на реальной статистике песочницы
за 28.10–04.11.2026 (14 игр, ~1100 игроков с бесплатной рекламы). Это не вердикт владельца: PASS/FAIL ставит только владелец.

## 1. Что показала статистика (все игры болеют одним и тем же)

| Игра | Игроков | Не загрузилась | ≥30 сек | ≥60 сек | Ушли на рекламе |
|---|---|---|---|---|---|
| Twilight Isle Classic | 429 | 13% | 50% | 40% | 36% |
| Archer in the Fog | 423 | 11% | 45% | 27% | 51% |
| Dreamverse | 261 | 7% | 28% | 19% | 41% |
| остальные 11 игр | 0–7 | — | — | — | — |

Пять болезней:
1. **Долгая загрузка** — каждый 9-й уходит, не увидев игру (game_ready < init).
2. **Скучное начало** — половина уходит до 30 секунд: титульный экран со стеной текста, непонятно что делать.
3. **Реклама в лицо** — interstitial сразу на экране смерти (~1-я минута) → почти половина закрывает игру.
4. **Нет цели и повода вернуться** — нет награды, нет прогресса между заходами.
5. **Слепота** — игры не шлют свои события, не видно, где игрок сдался.

Каталог открывается сам, только когда песочница наберёт пороги (≈100 игр и ≈5 мин среднего времени; точные — на карточке
песочницы в консоли, считается раз в день). Бесплатные рекламные запуски кончились (3 на аккаунт навсегда) — значит,
каждая игра должна сама удерживать тех, кто пришёл.

## 2. Обязательный набор «удержание» (вносить в каждую игру)

| # | Что | Как (проверено в Twilight Isle Classic 1.1.0) |
|---|---|---|
| R1 | **Мгновенный старт** | Первый заход — сразу в игру, без титульного экрана. Титул только для вернувшихся. Звук будится первым касанием/клавишей. |
| R2 | **Загрузка без текста** | Только полоса загрузки. Ожидание Bridge ≤ 2 с. `game_ready` — когда загрузочный экран уже убран. |
| R3 | **Обучение без слов** | Светящаяся пиксельная стрелка у героя указывает на следующую цель; на телефоне — пульсирующий круг-подсказка джойстика до первого касания. Стартовые тосты с текстом убрать. |
| R4 | **Подарок в первые секунды** | Ежедневный подарок (оружие/бонус среднего уровня) лежит в 2–3 шагах от старта и светится — игрок сразу делает первое действие и получает награду. Раз в календарный день, через `bridge.storage`. |
| R5 | **Rewarded-воскрешение** | На экране поражения кнопка «Ожить: смотреть рекламу» (текст обязан говорить про рекламу — правило 2.2.1), один раз за попытку (2.2.4), награда только при состоянии `rewarded` (2.2.5). |
| R6 | **Interstitial не поверх результата** | Показывать при нажатии «Ещё раз / Новый остров» (естественная пауза), а не в момент появления экрана поражения. Частоту не считать самим — её держит Bridge (`minimumDelayBetweenInterstitial`). |
| R7 | **Кнопки — иконки** | Никакого текста на игровых кнопках (особенно русского в английской версии). См. AGENTS.md «ЧИСТЫЙ ЭКРАН». |
| R8 | **Телеметрия** | `bridge.analytics.send`: `progression_started` (run), `progression_completed` (step_id: coins_25/50/75, all_coins, финал), `progression_failed` (step_id + t), `revive_offered/used`, `daily_gift`, и `performance_sample` раз в 30 с активной игры (контракт из get_game_telemetry_guide). Имена событий — постоянные, переменное — в данных. |
| R9 | **Без Esc** | Пауза на `P` (правило 1.5.2: Esc зарезервирован браузером). |
| R10 | **Версия сборки** | `GAME_VERSION` в коде и в имени архива (`<игра>-1.1.0`), чтобы сравнивать статистику до/после. |
| R11 | **Счётчик «СОСТАВ»** | Встроенный скрытый счётчик `INV` + `window.__INV()` (как в ASQURA): разделы из реестров игры, проверки `extra` для R1–R10, история `INV.hist` с итогом. Перед правкой и перед публикацией `lost` пустой, `now` не меньше базовой линии. Эталон: `playgama-games/twilight-isles/` (313). |

## 3. Порядок работы

1. Снять статистику: `get_game_telemetry_analytics` (неделя) → посчитать воронку init → game_ready → 30s → 60s и уход на рекламе.
2. Взять **текущую живую сборку** (sandbox `site.revision.archiveId`): `https://sb-<siteId>.games.playgama.net/<archiveId>/index.html` +
   все файлы, на которые она ссылается. Вырезать внедрённые хостом куски (скрипт `__GCAJP__`, `<link rel=canonical>`,
   `bootstrap.js`, блок `sbb*`). Стиль игры не трогать.
3. Внести R1–R10 **добавлением** (свой модуль `RET`, хуки `on()`), не переписывая принятый код.
4. Проверка Playwright: телефон, ПК, квадрат 1:1 — автостарт, стрелка, подарок, смерть → кнопка воскрешения → воскрешение
   ровно один раз → «Ещё раз» вызывает interstitial → перезагрузка показывает титул. Ноль ошибок в консоли.
5. Сверить `get_game_checklist` по номерам, назвать номера, которые не проверены.
6. Загрузка: `start_archive_upload` → PUT архива → `confirm_archive_upload` → ждать `PASSED` → `publish_sandbox`.
   Если сеть агента не пускает на S3 Playgama — workflow `.github/workflows/playgama-upload.yml` (push ветки с
   `playgama-upload/archive.zip` и `upload-url.txt`), затем удалить ветку.
7. Через 1–3 дня трафика сравнить метрики по `game_version`.

## 4. Известные блокеры каталога (чинить следующими шагами)

- **3.3.2 Звук**: звук, синтезированный в коде (Web Audio тоны), модерация не принимает — нужны файлы ogg/mp3.
  Готовая CC0-библиотека уже есть: `audio/library/` + `audio/SOUND_NEEDS.md` (раздел по каждой игре).
- **Сертификация** QA Tool (форма заблокирована `NO_CERTIFICATION`) — `get_archive_qa_tool_link` mode certification.
- Лидерборды на самом Playgama не поддерживаются (`leaderboards.type = not_available`) — не добавлять.
