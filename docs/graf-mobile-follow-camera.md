# GRAF — каноническое мобильное управление и следящая камера

**Назначение:** обязательный reference contract для всех наших игр с перемещаемым персонажем. Главный стандарт: [graf.md](../../graf.md), раздел 26.

**Реальный пользовательский референс:** присланный владельцем HTML «Остров сумерек(7).html» (2026-10-17). Это **описание поведения из исходного HTML**, а не утверждение, что данный файл уже опубликован в этом репозитории. Профиль исходника: Three.js r160, pointer controls и сглаженная orbital-follow камера.

## 1. Что конкретно делает исходник

- Игра рисуется в одном `<canvas id="c">`, закреплённом `position:fixed; inset:0; width/height:100%; touch-action:none`. `html/body overflow:hidden`, `overscroll-behavior:none`, HUD и touch overlay `position:fixed`.
- Touch mode определяется coarse pointer / отсутствием hover, а touch UI скрывается вне активной игры; ПК использует WASD/стрелки, space, мышь.
- В **левой половине экрана** touch `pointerdown` фиксирует `touch.stickId`, ставит центр плавающего джойстика в точку первого касания; `pointermove` ограничивает вектор радиусом **56 CSS px**, нормализует `vx/vy`; `pointerup/cancel` обнуляет input и скрывает джойстик. В исходнике диаметр подложки **128px**, рукоятки **52px**, адаптировать размеры к устройству.
- **Независимый палец на правой части игрового canvas**, при другом `pointerId`, получает `touch.camId` и вращает камеру `orbitBy(..., 0.008)`. События `stickId` обрабатываются ДО `camId`, поэтому перетаскивание джойстика **не вращает камеру**. Отдельный right-side drag может менять yaw/pitch. При отпускании применяется затухающая инерция.
- Команды движения `ix += touch.vx; iz += -touch.vy`, преобразуются **относительно ориентации камеры** `rig.yaw`, затем плавно интерполируются в горизонтальную скорость героя (ускорение на земле/в воздухе отличается).
- Кнопка прыжка справа — отдельный touch button, `pointerdown` включает `jumpHeld`/`jumpBuf`, `pointerup/cancel/leave` выключает. **В новом GRAF надпись «ПРЫЖОК» заменить на различимую пиксель-арт пиктограмму без видимого текста**.
- Следящая камера обновляет `tmpA` = `player.vis + player.vel * 0.22 + вертикальный offset 0.95`; вычисляет позицию `tmpB` на расстоянии `rig.dist` в направлении `rig.yaw/pitch`. `rayFree` сокращает расстояние до ближайшего препятствия; при необходимости камера приподнимается над преградой и затем возвращается.
- Плавность независима от FPS: `rig.pos.lerp(tmpB, damp(lerp(0.9, 5.5, blend), dt))`, `rig.look.lerp(tmpA, damp(lerp(1.1, 8, blend), dt))`, yaw/pitch/distance сглаживаются отдельно; `camera.position.set(...rig.pos)`, `camera.lookAt(rig.look)`. Возможна умеренная художественная вибрация на hit/опасность, но она не должна мешать управлению; для reduced motion уменьшается.
- Эта камера **следует за героем**, поэтому декорации могут **двигаться внутри неподвижного canvas**. Это нормально и требуется. Сама страница, canvas, fixed HUD, координаты touch-кнопок **не должны смещаться**. Нельзя путать «неподвижный экран» с «замороженная игровая камера».

## 2. Универсальное правило для всех игр

**PERSON MODE**
1. Один фиксированный canvas/viewport и закреплённый HUD без HTML-scroll, bounce и масштабирования страницы.
2. Плавающий или фиксированный левый джойстик перемещает 3D/2.5D персонажа относительно угла камеры. У него собственный pointerId; никакого прямого `camera.rotation` / `camera.pan` из stick-pointer path.
3. Следящая камера ПЛАВНО двигается за фактическим положением персонажа, сглаживает ускорения и по возможности учитывает препятствия, высоту рельефа, воды и коллизии; не проходит сквозь стены. Для разных игровых режимов допускается уменьшенный offset / иной pitch при сохранении принципа.
4. Свободная смена угла обзора осуществляется отдельным pointerId/жестом в разрешённой зоне (в референсе — правый палец на свободном canvas), никогда от пальца джойстика. Настраивать sensitivity/инерцию, ограничивать pitch/distance и исключать конфликт с правыми кнопками действий.
5. Кнопки действий справа — только уникальные семантически понятные **настоящие пиксель-арт пиктограммы** (локальные sprites, pixel-grid SVG, атлас с nearest-neighbor); никаких видимых слов «ПРЫЖОК», «УДАР», «СТРОИТЬ», «СМЕНА ОРУЖИЯ» на самой кнопке. **Разные функции — разные силуэты/глифы**, нельзя переиспользовать ту же иконку; активное/нажатое состояние различимо. Символы и набор действий по игре; пользовательская согласованная схема кнопок конкретной игры имеет приоритет по расположению и количеству.
6. `aria-label` и `title` содержат словесное назначение для accessibility/desktop tooltip; надпись скрыта визуально, но не из accessibility tree. Хит-область >=44x44 CSS px, safe-area, недопущение перекрытия миникарты и препятствий.
7. На ПК телефонные элементы полностью скрыты, работают клавиатура (WASD, стрелки, пробел) и мышь/тачпад с ЛКМ/ПКМ по контракту игры.
8. **EYE/MAP MODE** — отдельный режим: разрешён перенос карты пальцем по пустому полю и pinch zoom. Не переносить map drag handlers в joystick/person mode. Камера может работать по иным правилам, явно отмеченным текущим режимом.
9. **Исключения по виду игры**: для стратегий без героя и для специальных арен камера может быть намеренно фиксированной по решению владельца; для игр с героем описанная схема обязательна. Приоритет ранее принятого реального управления сохраняется, изменения не уничтожают механики.

## 3. Невозможные для PASS ошибки

- Джойстик перетаскивает страницу/DOM/canvas, или сам его pointerId поворачивает/перетаскивает камеру.
- Камера не следует за героем в режиме человека, рывками прыгает или пролезает через стену при обычном движении.
- Второй палец задевает джойстик, замораживает героя или кликает по скрытым меню; right camera orbit срабатывает через кнопку атаки/прыжка.
- Все кнопки используют одну и ту же пиктограмму, содержат видимые надписи либо значки нечитаемы в масштабе iPhone.
- Камера или UI меняет ширину/высоту/позицию canvas, `scrollX/Y` выходит из нуля.
- «Фикс» сводится только к CSS `overflow:hidden`, но движение и camera follow не протестированы.

## 4. Проверки до принятия

- Touch portrait реальное устройство (ориентир iPhone 11) и отдельно Playwright-emulation. Движение 10 секунд по 4 направлениям, с отпусканием; screenshot/video до/после, `worldPosition` героя меняется; camera rig distance/yaw/pitch и `camera.lookAt` следует за героем; canvas boundingRect неизменен, `scrollX/Y = 0`.
- Dual-touch: (1) левый джойстик + правая кнопка прыжка; (2) джойстик + независимое правое движение камеры; (3) отпускание одного пальца не сбрасывает другой; (4) `pointercancel`, app blur и повторный вход.
- Collision: герой обходит стену/склон, камера не проходит сквозь препятствие; finite movement, нет NaN, jitter и провалов FPS. Сравнить camera-target lag и frame-time p95, отсутствие визуальных регрессий.
- Сверить пиксель-арт кнопки: каждая action id имеет уникальный визуальный asset/id и контрастный силуэт, без видимых текстовых подписей, с `aria-label`, touch target и корректной семантикой.
- Проверить Eye/map drag и pinch отдельно, и desktop hiding/mobile keyboard. Технический тест PASS отличается от решения владельца PASS/FAIL.
