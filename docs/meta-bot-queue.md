### Handoff Claude: строгий watchdog ядра, без обхода

Сохранён штатный stuckSec=20; растягивать его до полного тайм-аута острова для обхода проверки нельзя. Планировщик теперь находится внутри bot-strategy.mjs: файлов бота снова ровно три, как требует актуальный automation/prompts/meta-games-bot-rollout.md (main 5425ade12ed725a0ca0fb9dcb3ce646c8ba9275f). Полный остров имеет предел 1200 с, но обе проверки отсутствия прогресса остаются 20 с. Каркас/сторож не редактировались.

В локальном строгом runOnce ПК (Playwright 1.62.1, НЕ CI) воспроизведён ложный сигнал ядра: герой прошёл от (22,50;37,50) до (26,60;46,66), подобрал пращу, собрал монету (stage=1), затем физически подобрал пистолет. Последние наблюдения: (30,55;45,73) → (29,33;46,55) → (27,14;46,37) → (26,60;46,66), HP=6, weapon=pistol. Игра продолжала продвигаться; ядро завершило её сообщением «уровень 1: герой застрял (20 с без приближения к цели)». Отдельная ошибка сравнения FPS 1,5 с CI-базой 3,8 относится к разному железу и не выдаётся за регрессию CI.

Нужно изменить каркас бота (делает Claude): в core.mjs watchdog внутри одного уровня не должен сравнивать новую цель с минимальным расстоянием до предыдущей. Учитывать фактическую смену stage, реальное движение по обходному маршруту и реальное уменьшение HP существующего combatant. Переменные best/bestAt сейчас общие для всех монет/боя внутри одного острова. Добавить в selftest кейсы «один уровень, смена подцелей», «обход препятствия с временным удалением от цели», «бой дольше 20 с с настоящим уроном»; неподвижная игра без урона должна по-прежнему краснеть. Нельзя заменить проверку случайным токеном прогресса, пропуском checks или выдуманной победой.

Также ядру нужны предусмотренные целью проверки: второй независимый заход должен пройти весь уровень, а не только снять hash; FIX должен наблюдать canvas/scroll во время удержания (включая 10 с), а не только до/после первого ввода. Текущий firstOnly=true не подтверждает полное прохождение второго захода. Это конкретные оставшиеся требования, а не выполненные проверки. До исправления и зелёного прогона с реальной победой PR #291 не сливать, ссылку платформы не менять.

Проверка производительности в каркасе: fpsBaseline=0 по умолчанию не сравнивает с прошлым запуском. Для выполнения требования без отчётов в Git можно сохранять маленький JSON с метриками в GitHub Actions cache по игре/экрану/параметрам рендера и восстанавливать предыдущий ключ. Новые полномочия CI, секреты, тарифы и платные сервисы не нужны. Эту часть защищённого workflow/core тоже делает Claude; текущий ручной FPS=3,8 для Twilight Island — документированная отправная CI-база, не автоматическое сравнение с каждым предыдущим прогоном.
