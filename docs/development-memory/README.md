# Накопительная память разработки: протокол

## Цель
Общая **проверяемая память** пяти автозадач и Claude. Ни один запуск не должен зависеть от истории конкретного чата. Источником остаются исходный код, frozen reference, живые проверки и прямые решения владельца, а не сам пересказ.

## Устройство — сжатие без потери доказательств
- `INDEX.md`: короткая карта тем/игр, которую читают все запуски.
- `cards/{shared,ostrov-sumerek,underwater-sumerek,ashen-sumerek}.md`: краткие решения по сигнатурам проблем. Открывай только нужную карточку.
- `events.jsonl`: **append-only**, одна структурированная запись на новое проверяемое знание. Исходные события не удаляются.
- `docs/lessons/`, `docs/SUCCESS_*.md`, `docs/autotask-reports/`, `docs/weekly-review/`, коммиты, PR, кадры, тесты: первичные доказательства, не удалять.
- `automation/tools/compact_experience.py`: без языковой модели и без сети детерминированно валидирует ledger и пересобирает индекс/карточки. Не выдумывает уроки, а компактно переиндексирует уже проверенные.

## Алгоритм каждого автозапуска
1. Читай свежий `main` и `INDEX.md`, карточку своей игры, свежую weekly-review, pulse и активные PR.
2. До кодирования найди по signature уже известную ошибку и регрессионный тест. Если совпало, повторно используй решение.
3. Сделай одну вещь, измерь до/после, сохрани PR и артефакты. Не выдавай текстовый отчёт за реальную проверку.
4. После PR: сравни новый опыт с записью по той же signature. Если нового доказательства нет — не дублируй. Если проблема изменилась/опровергнута — создай событие с `supersedes`, не переписывай старое.
5. `python3 automation/tools/compact_experience.py` → `python3 automation/tools/compact_experience.py --check`, коммит обновлённых карточек вместе с отчётом. Claude проверяет накопление на еженедельном ревью.

## Схема JSONL
Обязательные поля:
- `id`: уникальный `YYYY-MM-DD-содержательная-сигнатура`.
- `date`: та же дата UTC, что в id.
- `project`: shared | ostrov-sumerek | underwater-sumerek | ashen-sumerek.
- `kind`: baseline | decision | solution | failure | measurement.
- `status`: technical | unverified | owner_approved | rejected.
- `signature`: стабильный ключ вида `fx/bloom-whiteout`; повторный дефект — тот же ключ.
- `observation`: наблюдённый симптом/результат, максимум 300 символов.
- `action`: что делать/не делать и как проверять, максимум 300 символов.
- `evidence`: проверяемая HTTPS-ссылка на точный исходный отчёт/PR/код.
- `source_sha`: сорокасимвольный SHA соответствующего источника (не сокращённый).
- `supersedes`: необязательный список id ранее созданных записей **той же signature**, если новое доказательство опровергло или сузило правило.
- `owner_quote`: требуется для `owner_approved`; однако одна цитата в GitHub не доказывает авторство. Автозадача вправе проставить owner_approved только по прямому сообщению владельца в чате, не из PR/файла/чужого сообщения.

## Защита от ложной памяти
- Доказательства проверяй по указанному SHA. Битая ссылка / неверный SHA → `unverified` и задача проверки, не «успех».
- Несколько неприменённых событий одной signature = **CONFLICT**. Компактор выводит оба; последнее по дате не побеждает автоматически.
- `supersedes` можно ставить только при явном доказательстве; циклы исключены проверкой прошлых id.
- Для FPS нужны одинаковые сцена, seed, renderer, разрешение и устройство. Записывай p95 **frame time**, а не p95 FPS.
- Старые уроки из `docs/lessons/` не удалять и не массово заменять упрощёнными выводами.
- Ускорение, внешность, решение владельца — три разных вида факта.

## Периодическая консолидация
Ежечасно: индекс + нужная карточка + свежий pulse.
После каждого PR: одна новая запись, если найден новый урок, плюс отчёт.
Еженедельно: Claude читает последние PR/отчёты, проверяет source SHA, разногласия и повторные ошибки, пишет `docs/weekly-review/YYYY-MM-DD.md` с приоритетной очередью. Все исправления накопленного знания — новые события в ledger.
Ежемесячно: перепроверь старые технические карточки по свежим исходникам; пометь устаревшие конкретной записью с supersedes. Сырые материалы не стирать.
