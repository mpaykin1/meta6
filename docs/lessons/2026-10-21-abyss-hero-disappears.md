# Урок: рыбка-герой ABYSS GLOW мигала и исчезала (2026-10-21)

Игра: ABYSS GLOW, стенд ассет-пака (Three.js r160, instanced sprites). Правила: [abyss.md](../../abyss.md). Вердикт владельца по игре не выставлялся; этот файл — разбор ошибок, найденных владельцем на телефоне.

## Что видел владелец
1. Огромные жёлтые знаки перекрывают весь экран.
2. Рыбка иногда мигает и пропадает.
3. После правки рыбка пропала совсем, хотя управление работало.
4. Рыбка исчезает при полном развороте и при повороте строго вверх или вниз.

## Причины и исправления

| № | Причина | Исправление | Как ловить автоматически |
|---|---|---|---|
| 1 | HUD-canvas (сердца, жемчуг) в flex-колонке растягивался по ширине, высота шла по пропорции → иконки на весь экран телефона | у каждого HUD-canvas фиксированный CSS-размер = размер буфера; `align-items:flex-start; flex:none` | скриншот 390×844: HUD занимает < 15% площади |
| 2a | Неуязвимость после удара показывалась миганием героя (видим/не видим каждые 1/16 с) | убрано: герой всегда виден | — (решение владельца: герой не мигает) |
| 2b | «Битые пиксели» и мерцание применялись к герою, как к миру | у героя нет мерцания и меньше выпадения пикселей | — |
| 2c | Передний план (водоросли у камеры, чёрное тело) закрывал героя | объекты переднего плана рядом с героем на экране рассыпаются (dissolve) | в каждом кадре теста герой виден |
| 2d | Вид сверху / сбоку переключался туда-обратно на одном пороге угла | гистерезис: включение вида сверху при |угол| > 1.15, возврат при < 0.8 | — |
| 2e | Скрытая ошибка `undefined[0]` в `push()` останавливала игровой цикл | защитная проверка спрайта в `push()` | 0 `pageerror` в Playwright |
| 3 | Правка через `sed` вставила комментарий `//` в одну строку с `const want = ...` → объявление стало комментарием, имя `want` попало на другую переменную (вектор скорости) → вместо спрайта в `push()` уходил вектор → герой не рисовался | объявление на отдельной строке, переменная переименована в `wantView` | после каждой правки — прогон в браузере, проверка что герой отрисован |
| 4a | Отражение спрайта (плывёт влево) делалось отрицательным масштабом по X → треугольники вывернуты → **back-face culling** удалял квад. Так пропадали герой и все существа, плывущие влево | `side: THREE.DoubleSide` у материала спрайтов | кадры героя при движении во все 4 стороны |
| 4b | Плавное появление нового вида (dissolve-in) имело обратный знак: новая картинка исчезала по мере появления | условие `discard` исправлено: `hs > k` | то же |
| 4c | Скалы рельефа (3D) по глубине выступали перед героем | герой на z = 26, центр скалы z = −0.6r − 24 | то же |

## Правила, чтобы не повторилось (обязательные для abyss и всех игр со спрайтами)
1. **Отражение = DoubleSide.** Любой спрайт, который отражается отрицательным масштабом, рисуется с `side: DoubleSide` (или отражается через UV, а не через геометрию).
2. **Герой всегда виден.** Никаких миганий, выпадения пикселей, мерцания и перекрытия героя другими объектами без прямого запроса владельца.
3. **Тест «4 стороны».** После любой правки управления/героя: Playwright, телефон 390×844, удерживать ←, →, ↑, ↓ по 2 с, снять по 6 кадров на сторону; герой обязан быть виден в каждом кадре; `pageerror` = 0.
4. **Тест HUD.** Скриншот телефона: интерфейс не перекрывает игру (≤ 15% площади), каждая иконка своего размера.
5. **Правки кода не через `sed` в одну строку с комментарием.** После любой текстовой замены — прогон в браузере, а не только «замена прошла».
6. **Ошибка в кадре не должна останавливать игру молча.** Ловить `pageerror` в тестах; одна исключительная ситуация в `requestAnimationFrame` останавливает всю игру.
7. **Переходы (dissolve) проверять в обе стороны:** старое исчезает, новое появляется; в середине перехода объект виден.
