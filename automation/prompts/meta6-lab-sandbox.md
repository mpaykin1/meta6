0. ЗАЧЕМ ЭТО (прочитай, чтобы понимать смысл)
==================================================
- У Claude мало токенов, у тебя — безлимит. В основной проект meta6 сливать без Claude запрещено.
- Противоречие: тебе нужен доступ, чтобы работать, и нельзя давать доступ, чтобы ты ничего не сломал.
- Решение (ТРИЗ):
  • в пространстве: ты пишешь только в meta6-lab, в meta6 только читаешь;
  • во времени: ты работаешь всегда, Claude приходит, когда есть токены, и забирает готовое;
  • по условию: забирается только то, где бот прошёл все уровни, есть доказательства и владелец сказал «нравится»;
  • идеальный результат: Claude читает одну короткую карточку, а не весь код.
- Аналогия: meta6-lab — репетиционный зал, meta6 — большая сцена. Репетировать можно сколько угодно, на сцену выпускает только Claude.

3. ПОСТРОЙ ПЕСОЧНИЦУ (один раз)
==================================================
3.1. Создай публичный репозиторий mpaykin1/meta6-lab (fork своего же репозитория в тот же аккаунт GitHub не даёт — поэтому новый репозиторий + полная копия):
     git clone --mirror https://github.com/mpaykin1/meta6 meta6-mirror
     cd meta6-mirror && git push --mirror https://github.com/mpaykin1/meta6-lab
     (если mirror-push неудобен — клонируй main и запушь его как main в meta6-lab).
     В README.md meta6-lab в самом начале добавь: «ПЕСОЧНИЦА ChatGPT. Основной проект — mpaykin1/meta6. Отсюда в основной проект забирает только Claude. Правило: rules/06-rabota-ii-s-kodom/PESOCHNITSA_GPT.md».

3.2. Включи GitHub Pages в meta6-lab (Settings → Pages → Source: GitHub Actions). Пути в играх, где жёстко прописано https://mpaykin1.github.io/meta6/, в песочнице должны вести на /meta6-lab/ — исправь это в сборке сайта (подменой при сборке в _site), а не правкой исходников игр, чтобы при заборе в meta6 ничего не пришлось откатывать.

3.3. Сделай сайт с отдельной ссылкой на каждую идею. Workflow .github/workflows/lab-pages.yml в meta6-lab:
     - запуск: push в main и в любую ветку lab/**, плюс workflow_dispatch;
     - собирает _site так: корень = содержимое main; для каждой ветки lab/<имя> её содержимое кладётся в _site/preview/<имя>/;
     - публикует через actions/upload-pages-artifact + actions/deploy-pages;
     - после деплоя проверяет curl'ом, что https://mpaykin1.github.io/meta6-lab/preview/<имя>/meta-games/ отвечает 200.
     Пример ссылок:
       основная песочница:  https://mpaykin1.github.io/meta6-lab/meta-games/
       идея lab/ash-fog:    https://mpaykin1.github.io/meta6-lab/preview/ash-fog/meta-games/
     Если игр много и сайт тяжёлый — в preview/ клади только изменённые игры + meta-games/ + shared/.

3.4. Бот в песочнице. В .github/workflows/meta-bot.yml добавь ТОЛЬКО триггер:
       push:
         branches: [main, 'lab/**']
     Больше в нём ничего не менять. Бот должен проходить все уровни всех затронутых игр на каждой ветке lab/**.

3.5. Синхронизация с основным проектом. Workflow .github/workflows/sync-from-meta6.yml в meta6-lab:
     - раз в сутки (cron, например '17 3 * * *') и вручную;
     - забирает mpaykin1/meta6 main и вливает в main песочницы (fast-forward или merge без конфликтов);
     - если конфликт — сам разрешает в пользу meta6 (основной проект главнее), потом пересобирает Pages.
     После синхронизации ветки lab/** со статусом «В РАБОТЕ» перебазируй на свежий main.

3.6. Создай в корне meta6-lab файл LAB_QUEUE.md (очередь карточек, формат — раздел 5). Важно: в meta6 файлы-отчёты запрещены, а в meta6-lab LAB_QUEUE.md — единственный разрешённый файл-отчёт, это исключение из правила песочницы.

4. КАК РАБОТАТЬ НАД ИДЕЯМИ (постоянно)
==================================================
4.1. Одна идея = одна ветка lab/<короткое-латинское-имя> от свежего main.
     Примеры хороших имён: lab/ash-fog-intro, lab/archer-new-enemy-wisp, lab/broken-city-sound-harmony, lab/menu-unlocks-list.
     Плохие: lab/fix, lab/improvements, lab/all-games-update (непонятно, нельзя забрать по частям).
4.2. Размер: маленькие, понятные изменения. Ориентир — до ~300 изменённых строк на идею. Новую механику клади отдельным модулем (новый файл .js), а в игре — одна-две строки подключения. Так Claude заберёт её за минуту.
     Пример ХОРОШО: добавлен games/archer-in-the-fog/wisp-enemy.js (180 строк) + 2 строки подключения в index.html.
     Пример ПЛОХО: переписан весь index.html игры на 4000 строк ради нового врага.
4.3. Источник идей (что делать):
     - пункты RULES_CHECKLIST.md, которые у игр ещё не выполнены (см. games/<игра>/README.md — там честный статус);
     - новые вещи вперемешку (новый враг, объект, тайл, оружие, помощник…), собранные ТОЛЬКО из ассетов, которые уже есть в игре или в разрешённых эталонах;
     - оптимизация из RENDER_OPTIMIZATION_ROADMAP.md без потери графики;
     - всё, что владелец попросил в чате.
     Не менять то, что владелец уже принял (rules/08-pravila-otdelnyh-igr/ACCEPTED_BEHAVIORS.md), если он не просил.
4.4. Проверка перед статусом «ГОТОВО К ПРОВЕРКЕ» — все пункты обязательны:
     a) бот-прогон meta-bot.yml на этой ветке зелёный, все уровни пройдены;
     b) в консоли браузера нет ошибок;
     c) FPS не хуже, чем на main песочницы (бот пишет FPS);
     d) ЧИСТЫЙ ЭКРАН: в игровом режиме нет видимого текста вне меню;
     e) превью-ссылка открывается (200) и игра в ней реально запускается;
     f) git diff main...lab/<имя> не трогает запрещённые файлы из раздела 2.
4.5. НАШЁЛ ОШИБКУ → ОБЯЗАН САМ ЕЁ ИСПРАВИТЬ и только потом сообщать. Отчёт «я нашёл ошибку» без исправления запрещён. Если не можешь починить за разумное время — идея получает статус ОТКЛОНЕНО с причиной, а не «готово».
4.6. ДОКАЗАТЕЛЬСТВА: каждое утверждение («сделал», «бот прошёл», «ссылка работает», «FPS не упал», «запрещённое не тронуто») сопровождается ссылкой, SHA коммита или ссылкой на прогон GitHub Actions. Утверждение без доказательства считается ложным.

6. КАК CLAUDE ЗАБИРАЕТ (тебе делать не нужно, но учитывай)
==================================================
Claude читает LAB_QUEUE.md, берёт только «ГОТОВО К ПРОВЕРКЕ» + «Михаил: нравится», переносит модуль в meta6, дописывает свои части, прогоняет бота и ставит «ЗАБРАНО → SHA».
