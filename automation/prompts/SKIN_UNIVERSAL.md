# СКИН ПО ЭСКИЗУ — универсальная инструкция для ChatGPT (все игры)

Владелец пишет коротко: «Скин: эскиз <ссылка>, герой <игра/персонаж>». Всё остальное — здесь. Читать этот файл целиком в начале КАЖДОЙ сессии; порядок не менять.
Стандарт формата: rules/01-stil-i-grafika/SKINY.md (§1 формат пакета, §2 S1–S12, §8 лист деталей).

## Где работать
- Только mpaykin1/meta6-lab, ветка `lab/skin-<имя>`, один PR на скин. В mpaykin1/meta6 не писать.
- Эскиз скопировать в `skins/sources/<имя>/sketch.png`. Прогресс — `skins/sources/<имя>/STAGE.md` (текущий шаг, SHA, ссылки).
- Проверяет Claude комментарием в PR: `СКИН-ПРОВЕРКА: <шаг> принят` или `— исправить: …`. Без «принят» следующий шаг не начинать. Владелец смотрит только итоговую ссылку поиграть.

## Шаги (один шаг = одна сессия, потом ОСТАНОВИТЬСЯ)
**Ш1. Разбор эскиза** → `parts-sheet.md`: таблица всех деталей (имя, к чему крепится, как двигается: не двигается / вращается / качается / светится / кадры) + палитра 6–16 цветов, снятых с эскиза пипеткой. Только то, что реально есть на эскизе — ничего не придумывать.
**Ш2. Лист деталей** — рисовать ГЕНЕРАЦИЕЙ ИЗОБРАЖЕНИЙ, как художник (не кодом по пикселям):
- 2048×2048, фон ровно #FF00FF, без градиента и теней; между деталями ≥ 40 px; детали не касаются краёв;
- вид спереди, свет сверху-слева, стиль и цвета эскиза;
- дыры в броне сквозные (внутри #FF00FF), видимая в дыре механика — отдельной деталью;
- светящиеся детали и эффекты — БЕЗ ореола и размытия, жёсткий край (ореол добавит движок);
- эффекты (разряды, искры, дым) — ряд кадров одного размера, 6+ разных кадров;
- никакого текста, цифр, рамок;
- сдать `parts-sheet.png` + `sheet-vs-sketch.png` (слева эскиз, справа лист).
**Ш3. Ножницы** → `scripts/skins/cut-sheet.mjs` (один на все скины; если уже есть — только использовать): вырезать детали по фону #FF00FF, убрать розовую кайму, уменьшить до пиксель-арта (nearest), привести к палитре, разложить в `skins/packs/<имя>/parts|sheets|textures`. Сдать `cut-preview.png` — все вырезанные детали на тёмном фоне.
**Ш4. Сборка куклы** → `skin.json`: каждая деталь на свою кость, точка вращения, слой (2d / 2.5d / 3d), анимация со сдвигом фаз (волна по телу, не всё разом). Сдать `preview.png`: герой в игре спереди, сбоку, сзади рядом с эскизом.
**Ш5. Движение и сдача**: анимации, реакция на бег и вспышку, полный валидатор S1–S12 зелёный, ZIP, ссылка поиграть, карточка LAB_QUEUE.

## Всегда
- Критерий: не пиксельное совпадение, а по смыслу максимально похоже на эскиз (цвет, материал, силуэт, детали на местах, настроение). Перед сдачей сравнить самому; не похоже — переделать до сдачи.
- Нашёл ошибку → обязан сам исправить и только потом сообщать. Отчёт «я нашёл ошибку» без исправления запрещён. Красный прогон — сначала починить.
- Каждое «сделано», «проверка прошла» — со ссылкой на PR, SHA коммита или прогон GitHub Actions. Без доказательства утверждение ложно.
- Проверки не ослаблять (К4). Коммит и push каждые 10 минут (К11). Коммиты подписывать своим именем — подпись «by Claude» запрещена.
- Ответ владельцу — одна строка: «<шаг> сдан на проверку Claude» + ссылка на картинку шага.

## Уроки (не повторять)
- Рисовать пиксели кодом → «шум» и каша. Рисовать картинкой, потом уменьшать.
- Ореол вокруг светящегося на розовом фоне → розовая кайма после вырезания.
- Придуманные детали, которых нет на эскизе (антенна, пальцы, обод) → возврат.
- Формальные проверки зелёные ≠ похоже на эскиз. Смотреть глазами.
